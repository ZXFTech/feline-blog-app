## UI / manual

- [ ] **V-01 列表上下文**：打开 `/blog?content=%20目标词%20&orderBy=asc`，再验证重复 `content` 参数、空白搜索词和无效 `orderBy`。查询和可见说明均采用首个搜索值去除首尾空白的结果；仅 `asc` 为最早在前，其余为最新在前；页面具有 `h1`“文章”。覆盖 AC-1、AC-7、AC-11。
- [ ] **V-02 数量与上限**：在独立本地库准备超过 20 篇匹配文章，检查“共 N 篇，当前显示 M 篇”和“只显示前 20 篇”。N 来自成功结果 `total`，M 来自 `blogs.length`，不能把 M 说成总数。读取失败时不显示虚构的 0。覆盖 AC-1、AC-3。
- [ ] **V-03 两种空列表**：独立空库的 `/blog` 显示“暂时还没有文章”；普通本地库用唯一搜索词得到“没有找到匹配的文章”。使用“清除搜索”后只删除 `content`，保留排序、其他参数和片段，输入与地址同步，不向匿名读者增加新建操作。覆盖 AC-2、AC-7、AC-11。
- [ ] **V-04 防抖、排序与历史**：URL 已有旧搜索词时输入新词，在 500ms 内切换排序，确认新词和新排序只提交一次。再检查快速输入后清除，以及防抖期间前进后退；旧定时器不能重写目标 URL，目标 URL 决定输入和排序，卸载后也不提交草稿。覆盖 AC-2、AC-7。
- [ ] **V-05 列表服务端失败恢复**：在隔离环境临时阻止文章读取，打开带搜索、排序、其他参数和片段的列表地址。就地显示读取失败、“重试”和“返回文章列表”，不自动请求或跳转。恢复读取后用键盘重试，确认服务端重新查询并恢复真实结果，当前完整地址不变。覆盖 AC-3、AC-7、AC-11、AC-12。
- [ ] **V-06 详情服务端失败恢复**：对存在的文章重复 V-05 的真实读取故障流程。失败不能呈现为 404；恢复后标题、作者、标签、互动和正文来自当前文章，不能残留上一文章状态。覆盖 AC-3、AC-7、AC-11、AC-12。
- [ ] **V-07 文字缺页与文档重查**：分别访问无效 ID、未使用 ID 和本次测试创建后软删除的文章，检查文字 404、恢复入口和 noindex。经真实列表客户端导航进入软删除文章的缺页后，恢复同一条记录，用键盘激活“重新检查”，确认完整文档请求后真实标题与正文出现、404 消失，当前路径、查询和片段不变；另检查持续缺失和重查转临时读取失败。焦点与滚动遵循浏览器文档加载和片段定位，可回到 BODY，不强制聚焦结果标题。缺页不显示猫图、目录、互动或推荐查询；未流式输出时检查 HTTP 404，已开始流式输出时允许 HTTP 200。覆盖 AC-4、AC-7、AC-10、AC-11。
- [ ] **V-08 空正文详情**：使用正文为空字符串和仅空白的真实文章，确认标题、作者、标签、互动及相邻导航仍在，并准确显示“这是一篇空文章”。提示位于 Markdown 之外，原始正文值和 `blog-content` 根保留，空正文没有目录或伪造进度。覆盖 AC-5、AC-11。
- [ ] **V-09 相邻导航成功边界**：准备具有明确时间和 ID 顺序的文章，验证 `prev` 是更早、`next` 是更新，标题及正整数链接来自成功查询，跳转保持替换历史。分别检查单侧空邻居和两侧都空，只有成功的 `null` 才显示对应方向无文章，两侧空时说明“暂无其他文章”。覆盖 AC-6、AC-11。
- [ ] **V-10 相邻导航局部失败**：分别使用 Action 失败和 Promise 拒绝，检查临时失败、当前文章不存在和无效输入的不同说明。正文保持可读，失败不显示首尾判断；恢复后局部手动重试得到当前文章的真实邻居。真实页面单独拒绝相邻 Server Action 的传输，再恢复网络重试，明确该证据仅证明传输失败分支。覆盖 AC-6、AC-7、AC-11。
- [ ] **V-11 请求与页面内焦点隔离**：用可控 Promise 验证 A 到 B 再回 A，第一次 A 和 B 的迟到结果不能覆盖最后一次 A。检查卸载后不提交旧结果、当前重试期间不能重复发起、等待文本和 `aria-busy` 可感知。在 `router.refresh()`、框架 `retry()` 及相邻导航局部重试成功后，恢复按钮因成功移除时才把仍归属于该按钮的焦点移至当前结果或导航标题；用户已移走焦点时不抢回，使用 `preventScroll` 避免额外滚动。文档导航另按 V-07、V-12 检查。覆盖 AC-7、AC-10。
- [ ] **V-12 Blog 共用兜底与作者流程**：检查列表、详情、新建和编辑页共用的中文加载及意外渲染错误界面。加载有状态文本和隐藏装饰骨架；错误的“重试”使用框架 `retry()` 读取当前路由并保留地址。逐个从四种错误页用键盘激活原生“返回文章列表”链接，包含当前地址已有查询和片段、pathname 已为 `/blog` 的情况，确认完整文档导航到精确 `/blog`、正常列表出现、旧错误消失。返回不保留原查询和片段，焦点与滚动由浏览器处理，可回到 BODY；不要求保留旧控件或强制聚焦列表标题。列表和详情预期读取失败面板的同一返回链接也遵守该约定。回归作者新建、预览、提交、编辑及编辑页既有读取失败跳转；不声称恢复内存草稿或捕获提交事件中的任意异常。覆盖 AC-3、AC-8、AC-10、AC-11。
- [ ] **V-13 四主题与辅助操作**：在 1280×800 和 390×844，分别使用 light、dark、sugar、warm 检查上述状态。确认复用 Content、默认密度 NeuPanel、共享控件样式及主题变量；长文本、操作换行、滚动、阴影和焦点可用。用键盘完成恢复，在减少动态效果下没有持续装饰动画，结果温和播报且失败说明可感知。页面内重试不无故移动焦点；文档导航按 V-07、V-12 的浏览器原生约定验收。覆盖 AC-9、AC-10、AC-12。
- [ ] **V-14 安全 Album 与来源覆盖**：打开 `/album?component=blog-status`，逐一检查加载、空列表、搜索无结果、读取失败恢复、404、空正文及相邻导航成功和失败。恢复只推进本地内存，链接只记录意图且保留 Album 地址；从页面加载开始观察请求，确认没有生产文章 Action、业务写入或认证请求。确认只有安全导出列为 ready，来源覆盖审计通过。覆盖 AC-9、AC-10、AC-12。
- [ ] **V-15 公开读取与边界**：匿名直达正常详情，确认初始服务端输出含公开正文；回归未授权写入拒绝及已有 JWT HttpOnly Cookie 流程。检查读取继续使用 PostgreSQL、ActionResult 和脱敏日志，读者看不到原始异常，变更没有新增 schema、业务接口、依赖、生产配置或推荐查询。覆盖 AC-11、AC-12。
