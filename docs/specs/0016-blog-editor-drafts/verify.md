# 0016 的验收步骤

## Environment and evidence

本文件描述实施后的验证，不表示当前已经执行。使用经项目脚本核验的隔离本地 PostgreSQL 与安全测试作者，临时记录带唯一标记，按已知 ID 精确清理。另准备不同作者身份验证归属隔离；不得修改真实作者角色或删除已有内容来制造场景。

Playwright 使用隔离 PostgreSQL、测试身份服务和当前 SDK 会话。使用合成作者、其他作者和普通用户，单 worker 执行共享账号和可变数据场景。结果只记录脱敏证据，验收同时覆盖真实作者发布与匿名读取。

每项记录日期、提交版本、路由、身份、主题、视口、操作、实际结果与证据位置；未执行写为未验证。只有完整满足 index.md 的 AC-14 后，才可将 scope 33 记为 done。

## Thin end to end path

1. 匿名浏览 `/blog` 记录基线。作者打开 `/blog/new`，不输入并等待超过 1 秒，确认没有创建草稿。输入唯一标题、带缩进和首尾空行的代码及标签，停止修改后观察保存状态。数据库确认内容原样存在于 BlogDraft，Blog 与公开 API 中没有该文章。覆盖 **AC-1**、**AC-2**、**AC-3**、**AC-4**、**AC-13**。
2. 首次保存后检查地址包含 draft 标识，刷新恢复全部字段；在第二个作者登录上下文中恢复同一服务器草稿。这里的“第二个”上下文属于同一作者，另一个作者的越权检查另列。覆盖 **AC-5**。
3. 在保存请求尚未返回时继续输入新正文，然后点击提交。确认发布内容包含最后一次输入，公开详情与预览的正文结构、代码字符、标签一致。草稿从待发布列表移除，Blog 只创建一篇。覆盖 **AC-3**、**AC-4**、**AC-7**、**AC-8**。

## Published article isolation

1. 创建测试公开文章并建立测试点赞、收藏。记录 ID、authorId、createdAt 及关系。编辑标题、正文、同名标签颜色后等待草稿保存，匿名上下文读取列表、详情、相邻导航、总数及 `/api/blog`，仍为原内容和原标签颜色。覆盖 **AC-2**、**AC-8**。
2. 提交后重读上述路径，确认目标公开内容更新，ID、作者、创建时间和互动关系保持。检查原文代码、空行、Markdown 软换行及手写硬换行；不因编辑而再补空格。覆盖 **AC-3**、**AC-7**、**AC-8**。
3. 再次编辑，确认从当前工作副本开始，新的保存重新进入待发布列表。允许空草稿标题和空正文，提交后标题沿用“无标题”、空正文沿用 spec 0014 的公开展示。覆盖 **AC-5**、**AC-8**。

## Autosave and stale results

1. Vitest 使用可控时钟验证 999ms 未保存、1000ms 保存、每次修改重置计时。标题、正文与已确认标签都参与同一个计时器。覆盖 **AC-1**。
2. 模拟中文 compositionstart、compositionupdate、compositionend，组合期间即使暂停超过 1 秒也不保存，结束后重新计时且提交最终文本。覆盖 **AC-1**。
3. 第一次保存悬而未决时连续修改两个字段，确认表单可编辑、没有第二个在途请求，第一请求确认不覆盖新值也不显示当前已保存；最终只保存最新待处理快照。覆盖 **AC-4**。
4. 模拟服务端已提交但响应丢失。以同一 requestId 和快照重试，确认版本只递增一次；期间继续输入，再确认原请求后保存最新内容。相同 requestId 改变 payload 必须冲突。覆盖 **AC-4**、**AC-6**、**AC-7**。
5. 保存期间切换草稿、载入最新、卸载、再次挂载，旧计时器和 Promise 不得污染新实例。首次保存更新 URL 期间的新输入与焦点不能丢失。覆盖 **AC-4**、**AC-5**、**AC-9**。

## Publication transaction and retry

1. 连续点击提交、重复发送同一发布请求，验证只有一个公开结果；模拟提交事务成功但客户端未收到响应，再重试仍返回原 blogId。覆盖 **AC-7**、**AC-8**。
2. 在测试数据库中使提交事务的标签步骤失败，确认 Blog 内容、标签关联、publishedRevision 与发布回执均不发生部分提交，表单可继续编辑。覆盖 **AC-2**、**AC-6**、**AC-7**。
3. 保存、提交和删除从两个请求并发执行，验证原子版本条件；提交旧 revision 不得发布新草稿或覆盖已更新版本。覆盖 **AC-7**、**AC-9**、**AC-11**。
4. 在组件或隔离适配器中模拟数据库已成功而缓存失效、导航失败，确认显示已发布结果与查看入口，不清空表单后另建文章。覆盖 **AC-7**。
5. 发布事务成功后丢弃响应，同一作者的另一设备上下文使用此前读到的版本删除草稿，再由原页面点击“重试确认发布结果”。独立回执仍返回原文章 ID 和发布版本，公开文章不受删除草稿影响，不恢复草稿、不再写公开内容。结果不明期间普通提交保持互斥，确认入口可用且不会重复并发。覆盖 **AC-7**、**AC-9**、**AC-11**。
6. 在上一交错中继续软删除或在隔离库硬删除该测试文章，原发布确认应返回 deleted，页面显示“发布已完成，但文章现已删除”和返回草稿入口，不出现有效文章链接。再验证有效草稿被文章硬删除级联清理后，回执仍可确认原请求。篡改确认请求的版本或使用另一作者不能读取回执。覆盖 **AC-7**、**AC-13**。

## Conflict, failures and exit

1. 同一作者两个浏览器上下文加载相同 revision，A 保存后 B 保存。B 应停止自动保存并保留标题、正文、标签；复制正文精确对应当前输入。取消载入确认保留本页，确认载入成功后完整替换为服务器版本。覆盖 **AC-9**。
2. 两个页面在已有文章尚无草稿时同时开始，第一份保存成功，第二份不得创建第二个关联草稿；载入后得到唯一工作副本。覆盖 **AC-2**、**AC-9**。
3. 模拟网络断开、Action temporary_failure、传输拒绝、超出请求限制、invalid_input 和 unauthenticated。每项均保留输入，失败不显示已保存、不公开，重试或重新登录后可恢复。失败时不循环请求，冲突与认证失败时停止自动请求。覆盖 **AC-4**、**AC-6**、**AC-13**。
4. 修改后立即点击退出，确认先保存最终快照，再到精确 `/blog/drafts`。保存失败时留页，取消放弃确认继续编辑，确认放弃后返回草稿页且服务器此前已保存内容仍在。新建空白页退出不创建空草稿。覆盖 **AC-10**。
5. 刷新或关闭前有 dirty、saving 或结果不明状态时，在浏览器支持且已有用户交互的条件下检查原生离开提示；最新确认后不再提示。应用导航与浏览器历史跳转后重新打开草稿，应恢复最近一次服务器确认的版本；不要求全局路由拦截，不声称退出时已补存。覆盖 **AC-5**、**AC-10**。

## Draft management and authorization

1. 通过 Blog 作者操作区进入我的草稿，验证标题、类型、保存时间、继续编辑、分页及排序；创建至少 21 份本测试草稿覆盖分页，删除最后页末项后页面归到有效页。空列表与读取失败分别有正确恢复入口。覆盖 **AC-11**。
2. 删除新文章草稿及已有文章的修改草稿。取消确认不改变数据，确认后私有内容被清空、列表移除，公开文章保持原样。迟到的保存、首次保存重试和发布请求均不能复活删除记录。覆盖 **AC-9**、**AC-11**。
3. 草稿列表保留旧 revision 时另一设备保存，再删除应返回冲突并保留新内容。重复删除同一已删除草稿返回成功且不影响其他资源。覆盖 **AC-11**。
4. 匿名、普通 USER 和另一 ROOT 作者分别尝试草稿路由及直接 Action 调用。页面和 Action 都执行角色与归属检查，不能靠猜测 UUID、blogId 或请求 authorId 越权，资源不存在与他人资源的响应不泄露私有内容。覆盖 **AC-2**、**AC-13**。
5. 在临时数据库验证两条迁移链、新表约束、唯一关联、索引、RLS 和运行身份的最小权限。检查 PUBLIC、anon、authenticated 及 service_role 的拒绝路径，以及私有 metadata 和去敏日志。覆盖 **AC-13**、**AC-14**。

## Viewports, focus and safe showcase

1. 至少覆盖 320×568、390×844、768×900 和 1280×800，以及编辑容器 767.5px 和 768px 的边界往返。四主题均检查普通与全屏，长标题、多标签、长代码、宽表格和保存失败文案不撑宽页面。覆盖 **AC-12**。
2. 窄屏在编辑与预览间往返，宽屏开启并排预览；分别滚动后切换断点与全屏，确认表单、预览内容和各自滚动位置仍在。隐藏区域没有 Tab 停靠点。覆盖 **AC-3**、**AC-12**。
3. 键盘到达标题、标签、提交、预览与退出，检查焦点和阴影。全屏背景不可交互或滚动，Escape 的对话框优先级、退出全屏与焦点返回正确。删除或重试控件消失后不抢走已移开的焦点。覆盖 **AC-10**、**AC-11**、**AC-12**。
4. 检查保存状态播报与减少动态效果；Album 使用固定本地数据覆盖成功、失败、冲突、删除及全屏，确认不存在生产请求，维护实际导出的目录审计。覆盖 **AC-12**、**AC-14**。

## Private staging copy, spec 0009 contract

使用一次性 Docker 数据库分别执行两种检查。旧 staging 结构验证私有表的完整复制与拒绝路径，SDK 结构验证整库快照拒绝受保护的认证表。

1. 在 `pnpm db:local:test` 的唯一 Docker 项目中，用两个测试作者建立三份草稿，包含未发布正文、私有标签和删除标记，再建立一条没有现存文章与草稿的发布回执。使用实际 `app_exporter`、`NOBYPASSRLS` 和两条具名 SELECT 策略导出，恢复后逐字段比较内容与标识，检查全部源快照行数、目标 RLS、runtime 读取和 anon／authenticated 拒绝。覆盖 **AC-15**，回归 **AC-2**、**AC-7**、**AC-13**。
2. 分别移除策略、改为过滤条件、添加适用的 PUBLIC restrictive 读取策略、关闭已知表 RLS、增加未知 RLS 表、赋予导出角色写权限、sequence USAGE、BYPASSRLS、成员关系，以及让它拥有私有表但撤销自身 DML。每项都必须被拒绝，不能通过调整源行数绕过完整可见性检查。覆盖 **AC-15**。
3. 源快照持锁期间尝试修改策略，应被锁阻止；快照建立后修改草稿，目标必须保留快照中的原文。确认失败导出清理子容器，原有切换、fence、恢复与 volume 清理测试仍通过。覆盖 **AC-15**。
4. 策略变更先占锁时，快照必须等待，获得锁后检查新策略并拒绝过滤。源导出持有 staging 协调锁时，第二管理连接应返回 RECOVERY_REQUIRED，释放后可正常取得锁。覆盖 **AC-15**。

## Required commands

按本轮改动运行 `pnpm prisma:validate`、`pnpm prisma:generate`、`pnpm db:boundaries`、`pnpm db:local:test`、`pnpm lint`、`pnpm typecheck`、`pnpm build` 和 `pnpm test:ci`。公开链和 SDK 生产命名空间分别在一次性数据库回放，另运行迁移历史检查。

博客浏览器回归使用 `pnpm test:e2e:blog-drafts`。本机需要 Docker、OpenSSL、Chromium 和 WebKit。测试入口建立一次性数据库、测试签发方和 SDK 应用，使用回环接口，并把运行证据写到 Git 忽略目录。

已有相关 E2E 继续回归公开正文、阅读和状态行为；新增作者草稿专项验证真实端到端链路。报告区分静态检查、组件模拟、数据库集成、Album 与真实浏览器证据，不能将其中一种代替其他类型的验收。
