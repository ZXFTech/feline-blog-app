# Rationale: 0003 · 番茄钟按日布局与历史浏览

## Context

现有番茄钟把计时器、月历和整月历史放在一个客户端组件中。`selectedDate` 实际承载月份游标，翻月会把每月 1 日误当作选中日期。`Content` 在较窄宽度直接隐藏侧栏，因此把日历和历史放入侧栏后会让核心能力消失。

本次需要保留 spec 0001 的月查询、离线合并、冲突处理和本地日期归档，同时把页面改为按日浏览。计时器内部交互已经稳定，不应跟随布局调整一起重写。

`Content` 当前把主轨固定为 700px，且布局 CSS 没有使用已经存在的 `--container-content` 变量。清单详情和表单需要从固定项目列数切换为按自身容器宽度自然增减列，因此共享主轨必须提供足够空间，但不能代替项目网格决定列数。扩大共享主轨也会让依赖全局 700px 限制的旧页面一起变宽，因此页面宽度责任必须同时明确。

## Options considered

### 扩展现有组件并原地调整

保留现有数据与控制器，拆清页面协调、展示和操作职责。优点是兼容 0001，改动集中。缺点是 `Content` 的全局默认改变需要更广回归。

### 新旧布局并行切换

通过功能开关保留旧页面并逐步切换。回滚简单，但本次没有数据迁移或外部用户发布风险，双实现会带来不成比例的维护成本。

### 直接重写番茄钟页面与历史接口

新增单日查询并重新组织全部状态。接口看似更贴合页面，但会重复解决 0001 已完成的月边界、离线合并和冲突问题，也会增加每次选日请求。

### 只为清单增加宽版 `Content` 选项

清单页面显式选择宽轨，其他页面保持 700px。回归范围较小，但会让共享画布继续存在两套宽度规则，也无法让博客编辑器、Formatter 和其他密集页面自然使用宽屏。

## Rationale

选择原地调整。按月读取后客户端按日筛选，可以在不改变服务端契约的前提下完成主要用户目标。同一月份切换日期不产生额外请求，离线项仍可立即进入历史和日历。

`Content` 使用容器查询而不是沿用视口断点，因为重排条件是组件实际能否容纳三个区域。备选是固定视口断点，代码更熟悉，但在嵌套容器或侧栏宽度变化时容易过早隐藏或挤压内容。

共享默认行为是工程师明确选择的范围。备选是番茄钟专用布局选项，回归更小，但会让其他 `Content` 页面继续在中等宽度隐藏侧栏。规格因此明确四种插槽组合、两层容器结构和全站回归责任。

主轨最大宽度改为 96rem，并通过 `--container-content` 提供单一来源。1088px 与 1400px 继续表示布局形态切换点，不随最大宽度重算。若按 96rem 重算，单侧栏和三栏会推迟到极宽屏才出现，破坏已经验证的桌面布局。固定侧栏与主轨组成的整组轨道保持居中，避免超宽屏余白只落在一侧。页面本地容器负责阅读宽度，因此扩大共享画布不等于让文章正文采用 96rem 行宽。

清单项目网格不复用 `Content` 的 1088px 区域断点。它按自己的 content box、`12rem` 最小轨道、固定 `gap-3` 和项目数量使用 `auto-fit` 自然决定活动列数，因此项目卡片的减列边界与页面区域重排边界彼此独立。这样共享画布只负责提供空间，业务网格负责消费空间。

日期状态采用完全受控的日期键与年月值。备选是使用 JavaScript `Date`，代码更短，但携带日字段的月份算术会在月末跳月，系统时区变化也会让它偏离固定会话时区。

月份结果保存在当前会话内存，并以用户、时区和年月为键。会话代次与同键请求标识共同阻止用户切换和乱序响应污染结果。缓存不持久化，月份变为可见或 outbox 结算时刷新，失败时绝不使用其他月份数据冒充目标结果。备选是只保留两个数组，状态更少，但浏览月份与所选月份分离后无法同时可靠提供两组数据。

不采用功能开关。本次没有数据库迁移，旧布局可以通过单次代码回退恢复。高风险点是共享 `Content`，因此用生产调用清单、组件测试和真实页面检查控制风险。

## Content production surface inventory

无侧栏生产页面包括首页、Contact、Daily、Formatter、登录、注册、Todo、Tag、博客列表、博客新建、博客编辑、清单详情、清单编辑、清单回收站、清单新建，以及清单载入与错误页面。博客详情和清单列表使用右栏。番茄钟完整工作区使用左右栏。

已有本地宽度保护的页面包括登录、注册、番茄钟卡片、清单详情、清单回收站、清单新建和清单编辑。没有本地上限的博客列表与正文、博客编辑器、Todo、Tag、Daily、Formatter 和清单列表是主要回归面。博客正文、博客列表、Todo 和 Tag 保留 700px 视觉宽度。博客编辑器、Daily、Formatter 和清单工作页面使用宽轨。清单列表优先检查此前无法触发的宽布局分支。

## Migration plan

**Strategy**: no migration needed

实现可以在一个变更中完成。数据库和服务端接口不变。回滚时恢复旧 `Content` 样式和番茄钟组合方式即可，现有记录无需处理。
