# Neu 表面语义与交互契约：决策记录

## Context

`NeuDiv` 当前同时承担表面样式、悬停效果和交互事件。公开类型允许的组合多于 Sass 实际实现的组合，`elevated`、`lg` 和部分组合没有对应规则。`flat` 依赖不存在的选择器而碰巧呈现为无阴影。

部分调用点给 `div` 添加点击事件。WeeklyView 日期卡片因此缺少原生键盘操作。Tag 也把展示容器当作交互元素，并把关闭事件直接放在图标上。样式复用与元素语义绑定在一起后，调用方只能在视觉一致和正确语义之间取舍。

本决策不改变数据、API、认证或外部依赖。颜色、阴影尺寸、圆角、间距和现有普通动画保持不变。新的焦点样式与减少动态效果规则属于待批准的视觉调整，不在本轮实施。

## Options considered

### Option 1: 共享样式函数与语义元素

由严格类型的函数生成表面类名。`NeuDiv`、原生按钮、链接和 Tag 按需复用它，各自保留正确的 HTML 语义。

**优点**:

1. 样式只有一个来源。
2. 元素语义由真实行为决定。
3. 类型可以禁止无实现的组合。

**缺点**:

1. 所有旧引用需要在同一轮迁移。
2. 复杂 Tag 需要联合类型和分支渲染。

### Option 2: 多态 NeuSurface 组件

一个组件通过 `as` 属性渲染 `div`、`button` 或链接。

**优点**:

1. 调用形式统一。
2. 样式天然集中。

**缺点**:

1. 元素属性、引用类型和链接类型会形成复杂泛型。
2. 容易演变成缺少清晰边界的万能组件。

### Option 3: 保留 NeuDiv 并补充调用约定

继续允许事件透传，通过文档要求调用方补齐角色、键盘处理和无障碍属性。

**优点**:

1. 迁移量最小。

**缺点**:

1. 正确性依赖人工检查。
2. 每个调用点都会重复实现原生按钮已有的行为。

## Rationale

项目需要保留现有新拟态风格，但不应为了取得阴影而牺牲原生交互语义。共享函数是最小的公共抽象。它不会引入多态组件的泛型成本，也不会让调用方复制表面类名。

单次迁移适合当前规模。所有生产引用都在同一仓库内，旧值没有外部兼容需求。编译期联合类型可以立即暴露遗漏引用。
