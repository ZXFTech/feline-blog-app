# 0014. Blog 空状态与错误恢复修复

**Date**: 2026-10-22
**Updated**: 2026-10-23
**Status**: In Progress

验收清单见 [verify.md](verify.md)，决策背景见 [rationale.md](rationale.md)。

## Summary

列表、详情与相邻文章导航分别表达加载、没有内容和读取失败，并提供手动恢复入口。文章不存在时显示文字 404，正文为空时保留文章信息并显示“这是一篇空文章”。整个 `/blog` 共用中文加载与意外错误兜底，包括新建和编辑页。沿用现有查询、主题和组件，本轮暂缓文章推荐。

## Requirements

**User stories**:

1. 作为读者，我希望知道当前正在浏览哪些文章，并能区分尚无文章与搜索无结果。
2. 作为读者，我希望区分文章不存在、正文为空和暂时读取失败，并从当前位置恢复阅读。
3. 作为读者或作者，我希望 Blog 页面加载或意外崩溃时仍有明确的中文提示与可用操作。

**Acceptance criteria**:

1. **AC-1**: 列表具有可识别的“文章”页面标题，显示当前有效正文搜索词、排序和成功查询的结果数量。存在超过 20 篇结果时明确当前只显示前 20 篇，不把当前条数说成总数。
2. **AC-2**: 无有效搜索词且返回空列表时显示“暂时还没有文章”；有有效搜索词且返回空列表时显示“没有找到匹配的文章”，提供“清除搜索”。清除操作只删除 `content`，保留排序和其他查询参数，输入框与地址同步，旧防抖回调不能重新写回搜索词。
3. **AC-3**: 列表或详情的预期读取失败显示就地说明、“重试”和“返回文章列表”入口。重试重新执行当前 URL 对应的服务端读取，保留路径、查询参数和片段；不自动重试或自动跳转。失败状态不伪装成零条结果或文章不存在。
4. **AC-4**: 无效文章 ID、未找到或已软删除的文章进入框架 `notFound()` 缺页流程，显示文字“404”“文章不存在或已删除”，提供“重新检查”和“返回文章列表”。重新检查完整刷新当前文档，保留路径、查询和片段；资源恢复后显示真实文章，持续缺失或读取失败时显示相应状态。不显示猫图、目录或文章互动，不发起文章推荐查询；流式响应的协议限制见下文。
5. **AC-5**: 文章存在且正文为空或只有空白时仍为正常详情，保留标题、作者、标签、互动与相邻导航，并显示准确文案“这是一篇空文章”。不把提示写入 Markdown 内容，不把该状态当作 404，目录与进度继续按空正文规则隐藏。
6. **AC-6**: 相邻导航明确区分加载、成功、临时失败和当前文章已不存在。只有成功返回的 `null` 邻居才表示对应方向没有文章；失败时保留正文，在导航区域说明并提供局部手动重试。
7. **AC-7**: 重试期间防止同一操作重复发起，反馈可见；切换文章、快速搜索、修改排序或卸载后，迟到的请求与定时器不能把旧状态提交到新页面。搜索防抖尚未提交时切换排序，取消旧防抖并一次性提交当前输入与新排序；前进后退以目标 URL 为准，取消待提交输入。相邻导航从 A 到 B 再回到 A 时也不接收第一次 A 请求的旧结果。
8. **AC-8**: 整个 `/blog` 共用中文加载和意外错误兜底，错误兜底提供重新读取当前路由与返回列表。列表、详情、新建、编辑的错误页通过固定 `/blog` 的原生链接完整导航返回，当前 pathname 已是 `/blog` 时也能清除旧错误边界。新建、编辑页的正常表单流程及编辑页已有的读取失败跳转保持原有行为；页面兜底不声称能恢复内存草稿或处理提交事件中的异常。
9. **AC-9**: 新状态复用 `Content`、默认密度 `NeuPanel`、共享按钮与链接样式、现有主题及间距变量。light、dark、sugar、warm、桌面和窄屏均可读，操作可换行、可聚焦，阴影和焦点不被裁切，状态切换保持同一内容区域。
10. **AC-10**: 加载与重试通过状态文本及 `aria-busy` 表达，动态结果通过温和的状态播报表达，失败有明确可感知说明。隐藏骨架不进入辅助技术树，键盘可完成恢复，减少动态效果下没有持续装饰动画。页面内重试不无故抢走焦点；404 重查和页面恢复面板返回列表属于文档导航，焦点与滚动遵循浏览器原生行为。
11. **AC-11**: 公开正文继续由服务端输出，读取保持匿名可用，写入继续沿用现有角色与 JWT Cookie 检查。保留 `ActionResult`、现有日志脱敏和 PostgreSQL 边界，不新增数据库模式、业务接口、包依赖、生产配置或推荐服务，不向读者输出原始异常或内部信息。
12. **AC-12**: Album 有安全本地状态展示并维护来源覆盖，相关 Vitest、真实 Blog 页面与四主题浏览器验证、lint、类型检查、build 和所需安全测试账号下的 Playwright 通过。测试明确区分本地替身与真实服务端故障恢复的证据，不能用 Album 或网络中断替代所有真实页面验收。

## Decision

**Chosen option**: Option 1，在现有入口内补齐状态与恢复。

预期失败由当前页面或导航区域处理，意外渲染异常交给整个 `/blog` 的中文错误边界。所有重试由你手动触发：预期读取失败使用 `router.refresh()`，路由错误使用框架 `retry()`，相邻导航只重新调用自身查询。404 重查完整刷新当前文档，页面恢复面板的返回链接完整导航到 `/blog`，重新建立框架边界。由现有应用维护者随页面发布维护，无新增服务。

**Implementation skills**: `typescript-react-patterns` (`asyrafhussin/agent-skills`, `.agents/skills/typescript-react-patterns/`) · `tailwind-css` (`paulrberg/agent-skills`, `.agents/skills/tailwind-css/`)

## Feature design

### Data and boundaries

本项没有新业务实体、表、字段、索引或迁移。复用现有读取结果，下面的状态只存在当前页面内存中，不写入 Cookie、浏览器存储或数据库。

| Existing value | Type and relationship | Use |
| --- | --- | --- |
| `blog` | 现有 `getBlogById` 返回的文章或 `null`，包含作者与标签关联 | 文章身份、公开信息、正文及缺页判断 |
| `blogs`、`total`、`pageBean` | `getBlogList` 的文章数组、匹配数量和分页信息 | 当前结果、上下文和数量，仍读取第 1 页、每页 20 篇 |
| `prev`、`next` | 相邻文章的 `id`、`title`、`createdAt` 或 `null` | 仅在成功状态解释导航方向和边界 |
| `ActionResult` | `{ status: "success", data }` 或既有失败状态 | 区分读取成功、无效输入、资源缺失和临时失败 |

本轮只处理当前已生效的正文搜索 `content` 与时间排序 `orderBy`。不补做标签筛选、分页控件、标题搜索或推荐。设计来源沿用现有 `design.md` 与共享组件，不新增图片素材或视觉体系。

### State transitions and presentation

| Area | State and transition | Presentation and recovery |
| --- | --- | --- |
| Blog 路由 | 加载 → 页面，或意外异常 → 中文兜底 → 手动重试 | 同一 `Content` 主区内的标题、状态文本和轻量骨架；错误时显示“Blog 页面暂时无法加载” |
| 列表 | 成功有结果、无文章、搜索无结果、读取失败 | 保留页面标题和操作区；成功时才显示当前查询的数量，失败时不显示虚构的 0 |
| 列表更新 | 当前结果 → 搜索或排序待完成 → 新结果或读取失败 | 可以保留旧结果，但明确“正在更新文章列表”，不提前宣布新搜索无结果 |
| 详情 | 有文章 → 正常正文或空正文；缺失 → 404；临时失败 → 读取失败 | 缺页与读取失败不挂载文章阅读实例；空正文保留正常详情及原始正文根 |
| 404 | 缺页 → 重新检查 → 正常文章、仍缺页或读取失败 | 主入口为“返回文章列表”，另有“重新检查”，两者始终语义明确 |
| 相邻导航 | `loading → ready | error`，`error → loading` | 使用判别联合；error 区分 `temporary_failure`、`not_found`、`invalid_input`，不存在 loading 为 false 且失败被解释成空邻居的组合 |

列表标题使用 `h1`“文章”。普通上下文为“共 N 篇，当前显示 M 篇”；有搜索时明确“正文包含‘搜索词’”。排序说明分别为“最新在前”或“最早在前”。失败时保留有效查询说明，数量改为“结果暂不可用”。无搜索空态不向匿名读者显示作者创建操作；既有新建入口继续由 `PermissionAccess` 控制。

`content` 从 URL 的首个字符串值取得并去除首尾空白，空白视为无搜索；`orderBy` 仅在值为 `asc` 时正序，其他值按 `desc` 处理。页面显示和查询采用同一规范化结果。搜索输入受控；清除搜索撤销或使所有旧防抖回调失效。搜索防抖尚未提交时切换排序，先取消旧防抖，从当前受控输入取得去除首尾空白后的搜索词，与新排序一次性提交；词为空则删除 `content`，其他参数从当前 URL 保留。浏览器前进后退时取消待提交输入及旧防抖，以目标 URL 同步输入和排序，不重新提交离开前的草稿。排序、清除及搜索更新不用旧闭包覆盖其他参数。保留现有 500ms 搜索防抖，不修改全站防抖工具的契约。

相邻查询的 `prev` 是更早的文章，`next` 是更新的文章。成功的空方向分别显示“没有更早的文章”“没有更新的文章”，两者均为空时说明“暂无其他文章”。有邻居时显示实际标题，保持现有跳转方向与替换历史的行为。临时失败显示“暂时无法读取相邻文章”，当前资源不存在显示“当前文章已不存在，相邻文章不可用”，无效输入显示“无法读取此文章的相邻导航”。这些失败均不显示首尾判断，提供局部“重试”和“返回文章列表”，不自动移走已经显示的正文。

每次相邻查询关联文章 ID 和递增请求版本。ID 改变立即进入当前文章的 loading，旧结果不可见；切换、卸载和发起新请求后忽略迟到结果。捕获 Action 失败结果和 Promise 拒绝，重试期间只允许一个当前请求；底层请求不能取消时只禁止旧结果提交，不声称已中止服务端操作。

### Routes, interfaces and value sourcing

| Surface | Inputs | Output and failure mapping | Access |
| --- | --- | --- | --- |
| `/blog` | 当前 URL 的 `content`、`orderBy` | `getBlogList(1, 20, ...)`；success 按结果展示，预期失败显示列表恢复态，未知渲染异常上抛路由边界 | 公开读取 |
| `/blog/[id]` | 路由字符串 ID | `getBlogById(id)`；`invalid_input`、`not_found` 或 success 且 `blog === null` 调用 `notFound()`，临时失败显示读取恢复态 | 公开读取，沿用现有用户互动状态解析 |
| `src/app/blog/loading.tsx` | 无参数 | 整个 Blog 子树的中文等待界面；不读取数据库或判断登录 | 包括新建、编辑页 |
| `src/app/blog/error.tsx` | 框架提供的 `error`、`retry` | 固定安全中文说明、重新请求当前路由与返回列表 | 包括新建、编辑页的未捕获渲染异常 |
| `src/app/blog/[id]/not-found.tsx` | 框架缺页流程，不依赖传入文章数据 | 文字 404、重新检查当前 URL、返回 `/blog` | 仅公开详情缺页 |
| 相邻导航 | 当前有效文章 ID | 现有 `getAdjacentBlogs(id)`；成功使用邻居，失败按上述局部状态处理 | 公开读取 |

列表或详情的预期读取失败采用客户端 `router.refresh()`，重新执行当前 URL 的服务端读取。路由错误边界采用已安装 Next.js 16.3.3 的 `retry()`，重新获取并渲染子树；不能只用 `reset()` 清除错误后重放旧结果。这两种页面内重试都保留路径、查询和片段，不新增缓存层或后台轮询。

404 的“重新检查”启用 `BlogRecovery` 的 `reloadDocument` 模式，调用 `window.location.reload()` 完整刷新浏览器当前文档，保留当前路径、查询和片段。新的服务端结果可以是正常文章、仍缺页或临时读取失败。当前 Next 版本在同 pathname 保留已触发的缺页状态，因此该入口需要重新建立文档及框架边界。`notFound()` 仍在读取结果映射处调用，不被通用 catch 转为临时失败。

`BlogRecovery` 页面恢复面板中的“返回文章列表”使用固定 `<a href="/blog">` 的文档导航，复用共享 `buttonVariants` 样式。该约定覆盖列表和详情的预期读取失败、详情文字 404，以及列表、详情、新建、编辑的意外错误页；到达目标后清除原查询、片段与旧错误边界。当前 pathname 已为 `/blog` 时仍发起完整文档请求。保留原生链接的键盘、修饰键和新标签操作。相邻导航局部视图的返回链接继续沿用现有 `StyledLink`，不扩展为全站链接迁移。

加载文件不保证在同路径的每次查询参数更新时重新出现，因此搜索、排序和局部重试另有自己的 pending 文本与状态。各重试操作等待时有可见状态，禁止重复点击，完成后按新结果呈现，持续失败仍保留可再次尝试的入口。预期读取失败优先展示固定产品文案，不直接使用异常字符串。

| Action or display | Value | Source |
| --- | --- | --- |
| 列表上下文 | 搜索词、排序 | 当前 URL 规范化后的 `content`、`orderBy`，与当前查询输入一致 |
| 切换排序 | 本次一起提交的搜索词、新排序及其他参数 | 当前受控输入去除首尾空白，当前有效排序切换为另一方向，其余参数来自当前 URL；先取消旧防抖再提交 |
| 列表数量 | 总数 N、当前数量 M、显示上限 | 成功结果 `total`、`blogs.length` 和现有 `pageSize = 20`，不额外查询全站数量 |
| 列表空态 | 无文章或搜索无结果 | success 的空数组与规范化后的搜索词是否为空 |
| 文章详情 | 标题、作者、标签、互动及正文 | 同一次 `getBlogById` 的既有返回值，不从先前文章残留状态取值 |
| 缺页与空正文 | 404 判断、固定空正文文案 | `invalid_input`、`not_found` 或 success 且 `blog === null`，不包含 `temporary_failure`；空正文仅由存在文章的 `blog.content.trim().length === 0` 派生 |
| 相邻导航 | 标题、链接、方向、首尾 | success 的 `prev`、`next` 与 Action 已有的时间及 ID 排序规则；链接只用返回的正整数 ID |
| 预期读取失败重试 | 当前 URL 的服务端新结果 | 浏览器当前路由，由 `router.refresh()` 执行 |
| 路由错误重试 | 当前错误边界子树的新结果 | 框架提供的 `retry()`，按当前 URL 重新获取 |
| 404 重新检查 | 当前完整文档 URL 及其新读取结果 | `reloadDocument` 模式调用 `window.location.reload()`，不重建或拼接旧地址 |
| 页面恢复面板返回列表 | `/blog`，不保留原查询和片段 | `BlogRecovery` 固定的原生链接目标，不来自用户输入或旧路由闭包 |
| 局部重试 | 当前文章、请求身份与待完成状态 | 当前组件 prop `id`、本地请求版本和该次 Promise 生命周期 |
| 主题和布局 | 颜色、内边距、焦点和换行 | 现有 CSS 变量、Content、默认 NeuPanel、共享 Button 与链接 |
| Album | 状态、邻居和恢复结果 | 固定本地样例与内存异步适配器，不导入生产文章 Action 或认证 Provider |

404 使用框架的缺页与 `noindex` 语义。未开始流式输出时返回 HTTP 404；若上层 Suspense 已发送响应头，HTTP 可能是 200，由框架注入 noindex。现有根级 loading 已有这种边界，本轮不承诺所有导航和直达都得到线上的 HTTP 404，不为此增加代理数据库查询。可见页面标题与缺页语义在本项完成，不在本项改造文档 `<title>`；JSON-LD、OG、canonical、sitemap 和全站 SEO 继续属于 scope 13。

### Component, accessibility and safety contract

状态展示采用无业务依赖的 Blog 局部组件，复用 NeuPanel、按钮和链接；恢复交互单独作为必要的客户端边界，服务端页面继续查询并传入内容。相邻导航将无业务依赖的状态视图与生产查询连接部分分开，让 Album 只使用视图和内存适配器。props 使用 interface，状态使用判别联合，事件、DOM 和异步结果保持严格类型，不使用 `any`。

新增内容面板采用 default 内边距，父容器管理相邻区域 gap，纯结构包装如需零内边距须在调用处显式声明。页面状态维持当前阅读主栏宽度及应用壳，导航局部状态保留原来的导航区域，不用占满视口的转圈替代局部内容。不要求骨架与任意文章等高，不改共享 Content 的全站结构；本轮新状态自身的长文案、按钮换行、焦点和阴影边界必须可用。

加载状态使用持久状态文本、`role="status"` 与区域 `aria-busy`；骨架仅作装饰。结果播报按一次已完成查询更新，不逐字符或逐次渲染重复播报。客户端失败转换使用一处 alert 或等价可感知区域，首次服务端输出保留可见标题和说明，避免多个嵌套区域重复朗读同一错误。

页面内重试（`router.refresh()`、框架 `retry()` 和相邻导航局部重试）开始时保留合理的焦点；恢复按钮因成功而卸载时，仅把仍归属于该恢复按钮的焦点移到当前结果标题或导航标题，使用 `preventScroll` 避免额外滚动。用户已经移走焦点时不抢回。

404 重查和 `BlogRecovery` 返回列表会重新加载文档，焦点、滚动恢复及片段定位由浏览器处理，焦点可以回到 `BODY` 或浏览器决定的文档起点。它们不承诺保留旧文档的活动控件或滚动位置，也不额外对新文档执行标题聚焦或旧焦点还原。验收分别检查文档导航结果与页面内重试的条件聚焦，不混用两种约定。

“返回文章列表”是指向固定 `/blog` 的真实链接，重试是按钮。列表本身的返回入口另有清除搜索的效果，文案不得冒充“保留条件重试”。用户输入与标题均作为文本输出。空正文提示位于 Markdown 内容之外，原始正文与 `blog-content` 根保留；不改变阅读控制器、slug 或代码块规则。

权限、写操作、JWT 和 HttpOnly Cookie 继续由现有认证流程负责，页面兜底不执行写入或调用作者 Action。错误边界只处理其子树的未捕获渲染异常，不包含根 layout 失败或事件处理器中的任意异步异常。作者页崩溃重试可能重建表单，不能承诺保留未保存草稿；草稿与提交恢复仍归 scope 33。已有服务端 logger 与 `safeErrorContext` 保持脱敏，不新增浏览器原始异常上报或监控平台。没有新增生产配置、环境变量、密钥或外部连接。

### Safe showcase and critical test scenarios

Album 新增独立 `blog-status` ready 条目，展示加载、空列表、无搜索结果、读取失败后手动恢复、文字 404、空正文提示，以及相邻导航成功和失败。演示只用本地数据，重试只推进内存场景，返回和文章链接在沙箱中展示或记录意图，不改变 Album 路由。仅从 pending 家族移出本项真正可安全展示的导出，并维护目录来源审计。

1. 用真实本地文章检查列表标题、排序、总数与前 20 篇提示；使用唯一搜索词得到零结果，再清除搜索并检查 URL、输入和排序。URL 为旧搜索词时输入新词，在 500ms 内切换排序，确认新词与新排序一次性提交、旧防抖不再提交。再验证快速输入后清除，以及防抖期间前进后退以目标 URL 恢复且不重放草稿，覆盖 **AC-1**、**AC-2**、**AC-7**。
2. 用无效 ID、未使用 ID 和本测试创建后软删除的文章检查文字 404、noindex、返回与重新检查。经真实客户端导航进入软删除文章的缺页后，恢复同一资源，只点击“重新检查”，确认完整文档读取后真实文章出现、404 消失、查询和片段保留；另检查持续缺失和重查转读取失败。使用空字符串和仅空白正文的真实文章检查准确文案、元信息、互动和空阅读辅助状态，覆盖 **AC-4**、**AC-5**、**AC-10**、**AC-11**。
3. Vitest 对读取 Action 使用可控成功、失败及拒绝结果，验证列表和详情的结果映射、当前路由 refresh、错误边界 retry、无自动重试及重复点击保护。相邻查询以可控 Promise 验证失败后成功、真实首尾、缺失资源、A 到 B 到 A 和卸载，覆盖 **AC-3**、**AC-6**、**AC-7**、**AC-8**。
4. 真实页面中，对相邻导航的 Server Action 请求单独制造传输拒绝，确认只出现局部错误，恢复网络后点击重试得到真实邻居。此证据只证明传输失败分支，不代替服务端 `temporary_failure` 的验证，覆盖 **AC-6**、**AC-7**。
5. 列表与详情各完成一次真实服务端临时读取失败后，保持浏览器当前页面并通过按钮恢复。只在隔离的本地应用进程和已校验的本地数据库中安排可恢复的读取故障，恢复后确认读取重新执行、地址不变。不得向正式路由加入故障查询参数，不中断共享 staging 或现有日常开发数据库；没有隔离环境时该项明确记为未验证，覆盖 **AC-3**、**AC-11**、**AC-12**。
6. 检查 `/blog`、详情、新建和编辑页的共享加载与错误视图，分别验证中文提示、框架 `retry()` 和作者正常路径。逐个点击错误页的真实返回链接，确认完整导航到精确的 `/blog`、旧查询和片段清除、正常列表出现且错误消失，包含 `/blog` 同路径返回。文档导航沿用浏览器焦点，不套用页面内重试的标题聚焦断言；确认编辑页已有失败跳转仍保留，覆盖 **AC-8**、**AC-10**、**AC-11**。
7. 在 1280×800 和 390×844、四主题、键盘和减少动态效果下检查上述状态及 Album，验证语义、状态播报、焦点、换行和阴影，覆盖 **AC-9**、**AC-10**、**AC-12**。

真实文章及作者回归使用 `.env.e2e.local` 已配置的安全测试账号，临时记录带唯一标记并精确清理，不能为制造空列表删除已有文章。全站无文章的真实分支使用独立空本地测试数据库；普通共享本地库只运行唯一搜索词零结果场景。源码检查、Vitest、Album、传输故障及真实数据库读取故障各自记录证据；当前规格编写阶段未声称运行过应用或通过测试。记录“未验证”不是验收豁免，存在这些缺口时不能声称 AC-12 通过或将 scope 31 标为 done。

## Build plan

1. 先贯通真实列表的一条细线：查询、页面标题与结果上下文、预期失败面板、当前路由手动重试到恢复，并确认匿名读取和脱敏边界，满足 **AC-1**、**AC-3**、**AC-7**、**AC-11**。
2. 沿同一路径补齐空列表、搜索无结果、输入与 URL 同步、清除及防抖失效，验证真实查询和排序恢复，满足 **AC-1**、**AC-2**、**AC-7**。
3. 贯通详情的缺页、重新检查、临时失败恢复和空正文，保留正常正文输出及阅读辅助契约，满足 **AC-3**、**AC-4**、**AC-5**、**AC-7**、**AC-11**。
4. 完成相邻导航判别状态、局部重试、正确方向边界及请求版本隔离，再接入整个 `/blog` 的中文 loading 与 error，回归作者正常路径，满足 **AC-6**、**AC-7**、**AC-8**、**AC-11**。
5. 接入安全 Album 与来源审计，完成四主题、宽窄屏、辅助技术反馈和真实页面故障恢复证据；运行 `pnpm lint`、`pnpm typecheck`、`pnpm build`、`pnpm test` 和所需安全账号环境下的 `pnpm test:e2e`，满足 **AC-1** 至 **AC-12**。按 Beta 流程进入 `/check verify` 与 `/test`，未执行场景保留明确缺口。

## Consequences

**Positive**:

1. 读者可以据明确状态选择恢复操作，导航故障不会再被理解为文章边界。
2. 保留现有数据、渲染与权限路径，不增加运行服务或数据库维护负担。

**Negative / tradeoffs**:

1. 页面重试会重新执行当前路由读取，比相邻导航的局部重试范围更大；持续故障需要你再次点击。
2. 共用兜底覆盖作者页，但不解决编辑器草稿、提交恢复及已有失败跳转的问题。
3. 流式缺页的 HTTP 状态不保证始终为 404；文章推荐本轮不提供。
4. 真实服务端失败与全站空库验证需要隔离本地环境，不能只用网络拦截或组件替身证明。
5. 404 重查及页面恢复面板返回会重建整个文档，采用浏览器原生焦点、滚动与片段行为，不能保留旧组件状态或未保存的内存草稿。

**Neutral**:

1. 无数据迁移，可随页面代码回退；已有正文、目录及进度规格继续有效。
2. 本规格于 2026-10-22 经另一模型只读复核并由你确认，关联 scope 31；2026-10-23 按已验证的实现同步文档导航与焦点约定。流式缺页、作者未保存草稿及 C-06 staging 配置缺口继续保留，状态保持 `In Progress`，本次文档同步不代表验收完成。

## Follow-up

1. 相关文章推荐暂缓，后续如需加入，先明确缺失文章的关联信息来源及排序规则，或另行选择明确标为“最新文章”的导航模块。
2. 搜索、标签和分页扩展由 scope 10 承接，基础 SEO 由 scope 13 承接，阅读操作、容器收口与编辑恢复分别继续由 scope 29、32、33 承接。
