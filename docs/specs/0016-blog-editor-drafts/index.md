# 0016. Blog 编辑预览与操作修复

**Date**: 2026-10-24
**Status**: Accepted

## Summary

作者停止修改 1 秒后，自动将标题、Markdown 原文和标签保存为服务器上的私有草稿。点击“提交”才公开发布，修改已有文章时，读者继续看到上次提交的版本。编辑器移除无行为的“保存”按钮，补齐保存反馈、冲突处理、草稿管理和窄屏预览。

## Requirements

**User stories**:

1. 作为作者，我希望写作过程中自动保存，刷新页面或更换设备后仍能继续编辑。
2. 作为作者，我希望未提交的修改只有自己可见，公开内容由我主动提交。
3. 作为作者，我希望输入、预览、保存与发布采用同一份原文，失败或冲突时可以保留当前工作。

**Acceptance criteria**:

1. **AC-1**: 标题、正文或已确认的标签发生修改后，连续 1000ms 没有新修改才自动保存最新快照。连续输入重置计时，中文输入法组合期间不发起保存；组合结束后重新计时。仅打开未修改的编辑页不创建草稿。
2. **AC-2**: 自动保存只写入作者私有的草稿。公开列表、详情、相邻导航、数量、公开 API 和共享标签均不受草稿修改影响；已有文章继续展示上次提交的标题、正文与标签。另一作者不能读取、修改、提交或删除该草稿。
3. **AC-3**: 移除编辑器在换行前追加两个空格的转换。草稿与发布保存 textarea 实际提供的 Markdown 原文，不额外 trim 或改写正文；预览和详情继续共用 BlogMarkdown 与 CodeBlock，遵循 spec 0012 的正文、代码及安全规则。
4. **AC-4**: 编辑器明确显示“有修改尚未保存”“正在保存草稿…”“草稿已保存”及失败状态。已保存只代表当前表单快照已获服务器确认，旧请求成功不能把更新的输入标为已保存。自动保存期间仍可编辑，同一编辑器最多一个保存请求在途，后续修改合并为最新待保存快照。
5. **AC-5**: 草稿可在刷新和另一已登录设备中恢复标题、正文与标签。新文章首次保存成功后，当前地址包含可恢复的草稿标识；更新地址不清空表单、不丢失保存期间的新输入。已发布文章的编辑入口优先读取本人最新草稿。
6. **AC-6**: 移除“保存”按钮，保留“提交”。自动保存失败时保留全部输入，提供可操作的“重试保存”；重试期间防止重复调用。网络中断、请求拒绝、会话失效和字段无效均不能显示为保存成功，也不能自动公开内容。
7. **AC-7**: 点击“提交”先冻结当前表单，排空保存队列并确认最新快照已保存，再原子发布该版本。快速重复点击、请求重试及响应丢失不会重复创建文章或重复发布旧版本。发布成功后即使草稿被删除，原请求仍可确认既有发布结果；文章也已删除时明确反馈，不重建资源。成功且文章仍可用时进入可读到本次结果的公开详情，确认失败后保留表单并允许继续编辑或重试。
8. **AC-8**: 首次提交创建公开文章。之后提交保持原文章 ID、作者、创建时间、点赞和收藏关系，仅更新公开内容与标签。草稿始终保留最新工作副本；提交成功后从待发布草稿列表移除，再次修改后重新出现。不保存完整版本历史。
9. **AC-9**: 检测到服务器草稿版本已变化时停止自动覆盖，保留当前表单并提示冲突。作者可复制当前正文，或在确认放弃本页内容后载入服务器最新草稿；不提供强制覆盖。其他设备删除草稿后，迟到的保存或提交不能将其复活。
10. **AC-10**: “退出编辑”只有一个导航语义，目标为 `/blog/drafts`。有未保存修改时先保存最新快照，成功才离开；失败时留在编辑页，可重试或明确确认放弃未保存修改。刷新或关闭时通过 beforeunload 提供浏览器支持的离开提示。其他站内导航与历史跳转仅保证恢复最近一次服务器确认的版本，不承诺拦截全部跳转或在退出阶段完成异步保存。
11. **AC-11**: 新增作者私有的“我的草稿”页及 Blog 作者操作区入口。列表只包含本人尚未提交的草稿，显示标题、类型和最后保存时间，支持继续编辑与删除；具有加载、空态、读取失败和恢复反馈。删除前确认，删除草稿不改变已发布文章，并对并发修改进行版本检查。
12. **AC-12**: 桌面宽度充足时输入与预览并排，窄屏切换显示完整编辑区或预览区，分别保留内容和滚动位置。普通及全屏模式下，标题、标签、状态、提交与退出均可达；从 320 CSS 像素开始无意外整页横滚，内部阴影和焦点完整，支持四主题、键盘及减少动态效果。
13. **AC-13**: 页面与每个草稿 Action 均使用 spec 0019 的 User Center SDK 服务端会话、Blog 角色校验和服务端作者归属条件。私有路由不进入公开搜索索引。日志仅记录去敏错误。草稿表和发布回执表仅授予服务端所需权限，浏览器通过服务端操作访问草稿。
14. **AC-14**: 新编辑状态、冲突、草稿列表和删除确认具有安全的 Album 本地演示及覆盖归属，演示不调用生产 Action、API、认证或真实用户数据。真实作者闭环、数据库迁移与并发隔离、相关组件回归，以及项目要求的 lint、typecheck、build、Vitest 和安全账号 Playwright 均完成验证，未执行项明确记录。
15. **AC-15**: 按 2026-10-25 确认的 spec 0009 私有表复制规则，可信本地开发环境可以完整复制 staging 的 BlogDraft 与 BlogPublishReceipt，保留两表 RLS、产品作者校验和 Data API 隔离。导出账号保持只读且不能绕过 RLS；完整性与失败拒绝通过隔离 Docker 测试证明。刷新成功替换本地草稿和回执，不合并或上传；本轮实现验证不自动执行真实 staging 复制、角色变更或部署。

## Decision

**Chosen option**: 独立保存私有草稿，提交时更新既有公开文章。

新增 BlogDraft 和不含正文的 BlogPublishReceipt，公开 Blog 继续只存放已发布内容。沿用现有 PostgreSQL、Prisma 7、Server Action、认证和 UI 组件，使用版本号检测冲突，使用稳定请求标识与发布回执识别重试。界面设计来源为现有 design.md、主题 token 与共享组件。

**Implementation skills**: `typescript-react-patterns` (`asyrafhussin/agent-skills`, `.agents/skills/typescript-react-patterns/`)，`tailwind-css` (`paulrberg/agent-skills`, `.agents/skills/tailwind-css/`)，`supabase-postgres-best-practices` (`supabase/agent-skills`, `.agents/skills/supabase-postgres-best-practices/`)，`prisma-orm-v7-skills` (`gocallum/nextjs16-agent-skills`, `.agents/skills/prisma-orm-v7-skills/`)。

## Feature design

### Scope and existing contracts

本规格承接 scope 33。spec 0012 的共享渲染和代码展示规则继续有效，本轮接管其明确暂缓的输入转换与保存行为。spec 0014 的 Blog 加载与错误兜底继续复用，已保存草稿可重新读取，尚未确认保存的内存内容仍不能靠错误边界恢复。spec 0015 的 default 内边距、阴影和局部溢出规则继续适用。

当前 hasBlogRoles 只允许 ROOT，本轮保持该权限范围，并为作者路由补齐相同校验。空标题在草稿中保留为空，列表显示“无标题”，提交时沿用 trim 后为空则使用“无标题”的规则。正文继续允许为空。正文的原文边界是 textarea 的实际 value，浏览器自身的行尾规范化不算额外改写。

本轮提供一份最新草稿、服务器恢复与显式冲突处理。离线期间依靠当前页面保留输入与未保存提示，不引入浏览器持久草稿、历史版本、协作合并、定时发布或新的外部服务。不会批量移除已有文章中过去添加的空格。

### Data model

开发工具的数据复制遵循 spec 0009 的 Private draft copy contract。它复制全部作者、未发布内容、删除标记和无现存文章的回执，不采用产品草稿列表过滤条件。草稿与回执的产品访问规则不因此放宽。

Blog、User、Tag 和 TagsOnBlogs 继续使用现有模型。仅在 `prisma/postgres` 增加 BlogDraft、BlogPublishReceipt 及必要的反向关系，不向 legacy MySQL 写入。

| BlogDraft field | Type and nullability | Source and rule |
| --- | --- | --- |
| `id` | UUID，必需，主键 | 浏览器为当前编辑草稿生成一次，后续保存与重试复用；服务端验证格式 |
| `authorId` | 现有 User ID，必需，外键 | 只由服务端已验证会话取得，不能从请求指定 |
| `blogId` | Int，可空，唯一外键 | 新文章首次提交前为空；已有文章必须属于同一作者且未删除；建立后不可由普通保存重新绑定 |
| `title` | VarChar(191)，必需，允许空字符串 | 当前标题原值，发布时才使用既有标题规范化规则 |
| `content` | Text，必需，允许空字符串 | 当前 Markdown 原文 |
| `tags` | JSONB，必需，默认空数组 | 私有 `{content, color}` 快照，沿用现有每项 50 字符校验，不在自动保存时写 Tag |
| `revision` | Int，必需，默认 1 | 已持久化的工作副本版本，每次新的保存递增；请求里的 0 只表示尚未创建 |
| `publishedRevision` | Int，必需，默认 0 | 最近成功提交的草稿版本，始终不大于 revision |
| `lastSaveRequestId` | UUID，必需 | 最近一次成功保存的请求标识 |
| `lastSavePayloadHash` | Char(64)，必需 | 服务端对固定字段顺序的 `{blogId,title,content,tags}` JSON 计算 SHA 256，保留正文空白与标签数组顺序 |
| `createdAt` | timestamptz(3)，必需 | 数据库创建时间 |
| `updatedAt` | timestamptz(3)，必需 | 最近一次成功保存工作副本的数据库时间，保存时显式更新；发布及其重试不改变它，不使用每次更新自动改写时间的机制 |
| `deletedAt` | timestamptz(3)，可空 | 删除标记，用于阻止迟到请求复活已删除草稿 |

User 与 BlogDraft 为 1:N。Blog 与有效 BlogDraft 为 1:0 或 1:1；草稿最多关联一篇公开文章。作者外键随用户删除级联，文章硬删除时其关联草稿随之删除；业务软删除文章时拒绝继续保存或发布该文章的草稿。

BlogPublishReceipt 是发布成功的确认记录，不保存标题、正文或标签。每个成功确认的发布请求保留一条，只通过下列字段记录结果：

| BlogPublishReceipt field | Type and nullability | Source and rule |
| --- | --- | --- |
| `draftId` | UUID，必需 | 目标草稿 ID，与 publishRequestId 组成主键；不建立到草稿的级联外键 |
| `publishRequestId` | UUID，必需 | 客户端为该次发布生成的稳定请求标识 |
| `authorId` | 现有 User ID，必需，外键 | 已验证服务端会话，随用户删除级联 |
| `revision` | Int，必需，至少 1 | 该请求确认发布的草稿版本 |
| `blogId` | Int，必需 | 该次发布事务所得文章 ID；不建立到文章的级联外键 |
| `createdAt` | timestamptz(3)，必需 | 发布事务的数据库时间 |

回执随发布事务写入后不可改写。草稿删除、草稿的文章关联释放及文章软删除或硬删除均不移除回执，因而可确认原操作曾经成功；用户删除会清理其回执。本轮不设置自动过期，不保存内容修订历史。回执仅供作者的发布 Action 确认结果，不进入草稿列表或公开读取。主键支持按原请求定位，查询同时校验 authorId 和请求 revision。

数据库约束至少包括主键、作者外键、可空唯一 blogId、`revision >= 1` 和 `0 <= publishedRevision <= revision`。作者列表增加 `(authorId, updatedAt, id)` 索引。JSONB 不做搜索，不增加 GIN 索引。标题、标签结构与归属仍须服务端校验。

有效草稿列表条件为当前 authorId、deletedAt 为空、`revision > publishedRevision`，以及关联文章未软删除。按 updatedAt 倒序、id 升序排列，每页 20 条；服务端返回 total、实际 page 和 pageSize，越界页归到当前最后一页，空列表为第 1 页。

删除采用事务：核对作者和 expectedRevision，将 deletedAt 写入、revision 递增，清空 title、content 和 tags，并将 blogId 置空以释放唯一关联。只保留防止旧请求复活所需的标识、作者、版本、时间与请求摘要元数据，草稿读取均排除删除记录。独立发布回执与已发布 Blog 不参与删除；后续重新编辑文章可建立新的工作副本。重复删除同一已删除记录返回成功。

### Interfaces and value sourcing

草稿读写放在 `src/db`，沿用 ActionResult。查询不引入客户端直接数据库访问或新的 REST 写接口。下表名称为建议的稳定职责名，等价命名可由实施确定。

| Surface | Key inputs | Success output | Access and errors |
| --- | --- | --- | --- |
| `getBlogDraft` | draftId | 完整本人草稿、revision、publishedRevision、保存时间 | hasBlogRoles 加作者过滤；不存在、他人或已删除均 not_found |
| `getBlogEditorData` | blogId | 本人有效草稿，或本人公开文章的编辑种子 | 同时校验 Blog 作者和未删除；无草稿时读取不创建记录 |
| `getMyBlogDrafts` | page | rows、total、page、pageSize | 仅本人未提交草稿，临时失败可重试 |
| `saveBlogDraft` | draftId、blogId 或 null、expectedRevision、saveRequestId、title、content、tags | draftId、revision、publishedRevision、savedAt | 校验、归属、请求重试和版本冲突；返回 invalid_input、not_found、conflict 或 temporary_failure |
| `publishBlogDraft` | draftId、expectedRevision、publishRequestId | blogId、publishedRevision、publicationState（available 或 deleted） | 先确认本人既有回执，否则仅发布当前已保存版本；事务保证公开内容、发布标记与回执一致 |
| `discardBlogDraft` | draftId、expectedRevision | draftId | 本人草稿；版本变化则 conflict，不删除更新内容 |

未登录与角色不足分别沿用 unauthenticated、forbidden。传输拒绝及框架请求体上限错误由客户端捕获，保留表单并给出可理解的失败反馈；不提高现有 Server Action 请求体上限，不显示原始异常或堆栈。

| Produced value | Source |
| --- | --- |
| 当前标题、原文、标签 | 受控表单状态，初始来自 getBlogDraft 或 getBlogEditorData |
| authorId 与权限 | hasBlogRoles 返回的当前用户，关联查询再次含作者条件 |
| 草稿标识 | 当前编辑实例一次生成的 UUID，或已保存草稿返回的 id |
| 保存与提交请求标识 | 每个逻辑操作一次生成的 UUID，结果不明时复用原标识与原输入 |
| 保存版本与保存时间 | saveBlogDraft 的数据库确认结果，不使用客户端请求发出时间冒充成功 |
| 是否有未保存修改 | 当前表单快照与最近确认快照比较，加在途及排队状态 |
| 是否列为待发布草稿 | 数据库 revision 大于 publishedRevision，排除 deletedAt 与软删除文章 |
| 草稿类型与继续编辑地址 | blogId 是否为空；为空使用 `/blog/new?draft=<uuid>`，否则 `/blog/edit/<blogId>` |
| 列表标题与保存时间 | title 为空时显示“无标题”；updatedAt 的 ISO 时间在客户端按浏览器时区本地化，首次输出避免 hydration 差异 |
| 新公开文章的 ID、作者与创建时间 | 提交事务创建 Blog，作者来自会话，创建时间由数据库取得 |
| 发布重试的文章 ID 与确认版本 | 按 draftId、publishRequestId 定位的本人 BlogPublishReceipt；必须匹配请求 expectedRevision，即使草稿已删除也能读取 |
| publicationState 与已发布文章入口 | 按回执 blogId 检查本人 Blog 是否存在且未软删除；存在为 available 并提供详情链接，否则为 deleted 并明确反馈 |
| 公开文章内容与标签 | 提交目标 revision 对应的草稿快照；标题按既有规则处理，正文保持原文 |
| 复制正文 | 用户主动触发时读取当前 textarea 原文，不读取剪贴板 |
| 预览、主题、密度与布局 | 当前表单正文、BlogMarkdown、CodeBlock、全局 token 和实际编辑容器宽度 |

### Autosave, retry and concurrency

客户端使用可区分的保存状态和单一保存控制器，不能靠 Button 的 loading 代替函数级保护。每个保存请求绑定 draftId、编辑会话代次、固定输入快照和 saveRequestId。更换草稿、载入服务器版本及卸载时撤销定时器，并阻止旧异步结果提交到新实例。

1. 字段修改立即更新表单并进入 dirty。停止修改 1000ms 后提交快照。输入法组合中暂停计时与保存，组合结束后再计时；尚未确认到标签集合中的标签输入不作为已选标签保存。
2. 请求在途时继续接收输入。新的 1000ms 等待可与请求并行，但下一请求只能在前一请求确认后发起；等待已到期则保存最新快照，否则继续等剩余时间。不为每个中间字符积累队列。
3. 成功只更新该请求的已确认快照和版本，不能回写覆盖当前表单。当前表单仍有更新时继续显示未保存或正在保存，直到最新快照确认。
4. 保存失败后显示持久失败反馈和“重试保存”，不循环自动重试。若有结果不明的旧请求，先以原 requestId 和原快照确认结果，再保存当前最新快照；不能将改过的正文复用到同一个 requestId。新输入仍可保留并排队，冲突或认证失败时停止自动发起请求。
5. 服务端已存在同一 lastSaveRequestId 且摘要相同时，返回该次确认版本，不重复递增；同标识不同输入为 conflict。其他请求必须匹配 expectedRevision，保存、提交与删除使用同一草稿的事务串行化或等价的原子版本比较。
6. expectedRevision 为 0 时才允许创建不存在的 draftId。若关联 blogId 已有另一份工作副本，返回 conflict，通过已确认的载入流程重新读取该文章最新草稿。deletedAt 非空时任何保存都返回 not_found，不能按首次创建处理。
7. 冲突后保留标题、正文与标签，显示“草稿已在其他位置更新，已停止自动保存”。提供“复制正文”和“载入最新草稿”；后者使用 AlertDialog 明确会替换本页全部编辑内容。确认后读取成功才原子替换表单、草稿标识和版本并重置控制器，读取失败仍保留原内容。复制失败保留可选择文本并提示手动复制。
8. 会话失效时显示登录状态说明，保留输入；重新登录入口可在新标签页打开，回到编辑器后由作者重试，以服务端再次验证为准。

首次成功保存新文章后，使用原生 history.replaceState 保留现有 history.state，仅为 `/blog/new` 更新 draft 查询参数和保留其他现有参数，不重挂载编辑器。刷新时由服务器解析该参数并读取本人草稿。保存前的空白新建页仍为新文章，不默认恢复任意“最近一篇”草稿。已发布文章保持 `/blog/edit/<id>`，从对应唯一有效工作副本恢复。

### Submit and public data

“提交”开始时立即设定函数级互斥状态，停止防抖并冻结标题、正文、标签及重复提交、退出操作。保存控制器先完成结果不明的旧保存，再保存冻结的最新快照。即使首次提交的是空文章，也先创建可提交的草稿版本；任何保存失败都终止发布。

publishBlogDraft 只接受 draftId、目标版本与请求标识，不接收第二份正文。完成身份校验后优先查询本人既有发布回执，匹配原请求与目标版本时只返回已提交结果，不受草稿已删除或当前版本已变化的影响；同请求标识改用不同目标版本为 conflict。

没有匹配回执时，短事务锁定或原子占用本人有效草稿，事务内再次检查回执与目标版本，随后创建或更新 Blog、同步标签、写 publishedRevision 与 blogId，并插入该请求的回执。既有文章的 authorId、id、createdAt、互动计数和关系不变；新文章的 createdAt 从首次公开提交开始计算。草稿上的发布版本标记只判断是否待提交，成功操作的确认来源是独立回执。

自动保存不调用现有 upsertTags。提交时才在同一事务中解析私有标签快照并沿用现有用户范围标签关系，正确处理现有 citext 唯一语义，避免同批同名标签导致重复关联。标签颜色仍沿用现有共享标签语义，但提交前绝不改变公开颜色。

若目标仍是当前 revision 且已经发布，新请求仅确认既有公开结果，并在同一事务中保存该请求的回执，不再次写公开内容。没有匹配回执的其他旧版本请求返回 conflict，已删除草稿返回 not_found。草稿标记、标签、公开内容与回执必须一起提交或一起回滚；删除或软删除资源一律不重新创建公开文章。事务中不执行外部网络请求。

事务成功后失效 `/blog`、目标 `/blog/<id>` 与 `/blog/drafts` 的路由数据，再导航至公开详情；当前详情须读到本次发布结果。发布响应丢失时保持同一请求标识和目标版本，显示独立“重试确认发布结果”入口，冻结中的普通提交不承担该入口职责，不能退回旧的 createBlog 新建流程。结果不明期间保留输入并保持冻结，确认请求仍须函数级防重入。

匹配回执后查询文章的当前可用性。publicationState 为 available 时保留“查看已发布文章”入口；为 deleted 时显示“发布已完成，但文章现已删除”，提供返回我的草稿的入口，不显示可用文章链接，也不恢复草稿或重新发布。暂时的缓存失效或导航失败不撤销已提交的数据库事务，保留已确认结果供恢复，不能触发另一篇新文章。

成功前不清空本地表单。只有确认发布失败时才解除表单冻结，恢复后可编辑与重试；成功后保持发布结果状态直至导航或作者通过结果入口离开。旧保存回调不能在发布后重新标出一份过时的未提交草稿。

### Draft page and editor UX

`/blog/drafts` 使用现有 Content 外壳，标题为“我的草稿”，提供“新建文章”和“返回文章列表”链接。作者操作区在“新建”旁增加“我的草稿”。每行显示标题、“新文章草稿”或“已发布文章的修改”、最后保存时间、“继续编辑”和“删除草稿”。草稿只显示最新快照，不增加搜索、历史版本或撤下公开文章操作。

加载使用中文状态；空态为“还没有待发布的草稿”并提供新建入口。读取失败保留页标题与手动重试；删除失败保留条目和明确反馈。删除确认明确“已发布文章会继续保留”。使用行上已读 revision 删除，版本冲突则不删除并提示重新读取；成功后更新当前页及总数，焦点仅在仍属于被移除控件时移到下一条操作或列表标题，使用 preventScroll。

退出使用单个真实链接，href 固定为 `/blog/drafts`，不再用 Link 包裹 Button。普通点击在 dirty、saving 或 failed 时阻止立即导航，先排空保存队列；成功后导航，失败则提供重试与 AlertDialog 的“放弃未保存修改并退出”。没有修改的全新页面直接离开，不创建空草稿。已被确认保存的草稿不会因“放弃未保存修改”而删除。

dirty、saving 或结果不明时注册 beforeunload 提示，最新快照确认后移除；浏览器是否展示提示遵循其自身交互限制。该事件不拦截 App Router 的站内导航或历史跳转，本轮不增加全局路由拦截或伪造历史记录。明确的“退出编辑”入口执行上面的保存流程；其他离开、完整关闭、进程崩溃和错误边界重建只保证可恢复最近一次服务器确认的版本，不依靠卸载发请求。

正文预览继续使用当前 BlogMarkdown。编辑容器实际宽度至少 768px 时，开启预览后左右等分可用空间，并保留 default gap；低于 768px 时用有状态名称的“编辑”“预览”切换，一次显示一个完整区域。输入和预览保持独立滚动位置，断点往返不重置表单或重复创建渲染分支，隐藏区域不留可聚焦控件。

全屏沿用同一份受控表单和预览状态，占用当前动态视口高度并使用当前主题背景。工具栏、标题、标签和状态参与高度预算，编辑区使用剩余高度和 min-height:0，工具区允许换行。全屏期间背景不可交互或滚动，焦点保持在编辑区域，Escape 退出全屏并回到进入控件；弹出确认对话框时先由对话框处理 Escape。采用现有模态和焦点管理能力，不新增平行组件体系。切换全屏不会提交、清空或停止应进行的保存。

复用 NeuPanel、Button、InputField、TagEditor、AlertDialog 和 cn。内容容器默认使用 default 内边距，纯组合层的 p-0 或其他密度须显式声明。隐藏原生滚动条但保留滚动，不用整页裁剪掩盖超宽。持久状态使用一处 role=status；失败、冲突及删除反馈可被辅助技术感知，不在每个字符或每次渲染重复播报。

### Security, observability and configuration

每个入口先校验 Blog 角色，每次读写查询同时含当前作者和资源条件，UUID 不作为授权凭据。公开 getBlogList、getBlogById、getAdjacentBlogs 及 `/api/blog` 继续仅查询 Blog，不联查或返回 BlogDraft。私有页面使用动态当前会话读取，不进入共享用户缓存，metadata 使用通用编辑标题和 noindex，不把草稿文字放入公开社交元数据或 sitemap。

两条迁移链各追加草稿与回执表的迁移。本地和隔离 staging 使用 `public`，SDK 生产使用 `feline_sdk_prod`。迁移启用 RLS，撤销 PUBLIC 与 Supabase Data API 角色的访问，并按目标向服务端运行角色授予所需权限。作者归属由 SDK principal 提供，读写查询使用该身份的业务用户 ID；RLS 限制数据库角色直接访问。

沿用 logger、ActionResult 和 safeErrorContext，仅记录操作、资源 ID、请求 ID、版本及可安全分类的错误，不记录正文、标签快照、完整输入、凭据或剪贴板。保存成功不弹出逐次 toast；状态区承担常规反馈。无需新服务、环境变量或密钥，沿用当前连接池、超时和请求大小边界。

Album 将表单展示与生产查询、保存控制器分开，使用固定本地快照和内存适配器演示 dirty、saving、saved、失败重试、冲突、窄屏切换、全屏及删除。新增或更新实际导出的覆盖归属；演示导航只记录意图。代码和展示样例仍复用已有共享正文。

## Migration plan

**Strategy**: 新增私有草稿存储，逐段接入既有编辑流程，公开读取仍使用 Blog。

**Phases**:

1. 在隔离 PostgreSQL 上验证两条向前迁移。生成客户端，从空库回放，并检查新表约束及各目标运行角色的权限。现有文章继续按原样公开展示，作者编辑时按需创建私有草稿。
2. 将作者页接入草稿保存与唯一的提交发布入口，复用或内聚现有 createBlog、updateBlogById 的事务逻辑；清理不再使用的客户端直接创建或更新入口，避免提交失败后走另一条创建路径。
3. 完成真实本地闭环后按既有受保护部署流程部署迁移，再部署依赖新表的应用。远程 staging 与生产操作继续遵循数据库手册的门禁，不在规格编写阶段执行。

**Rollback**: 应用回退时保留新增表与草稿数据，公开文章无需数据回滚。旧编辑器不具备草稿恢复能力，回退期间应暂停作者编辑写入，待恢复新版本后继续；不能通过删除新表或复制草稿到公开文章来回退。

**Risks**: 自动保存增加短写入，按 1 秒防抖、单请求及索引控制。新表权限和标签共享副作用必须独立验证。清理旧输入转换只影响后续输入，不修复历史已保存空白。

## Consequences

**Positive**:

草稿与公开版本具有清晰边界，作者能跨设备恢复，预览与发布使用同一原文。公开读取路径与已有文章身份保持稳定。

**Negative / tradeoffs**:

新增迁移、私有管理页和保存状态机；服务器故障时未确认修改只能暂留当前页面。不同设备同时编辑需要作者主动处理冲突。删除保留少量无正文的防重放元数据，成功发布的请求另外保留不含内容的确认回执。

**Neutral**:

这份规格的确认确定设计，scope 33 的实施与验收完成后才推进为 Accepted。
