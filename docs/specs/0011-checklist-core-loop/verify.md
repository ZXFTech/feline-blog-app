# 0011. 确认清单核心闭环：运行时验证

本文件用于 `/check verify`。验证必须驱动真实应用和 PostgreSQL 数据，不以构建成功代替运行时证据。

## Preconditions

- 使用本地 PostgreSQL 开发环境并从空 verify 数据库重放全部迁移。
- 准备两个普通用户 A 和 B，不使用跨用户管理员捷径。
- 用可控时钟或短截止时间覆盖到期边界。
- 桌面宽度至少覆盖 1440、1200、900 和 390 像素。
- 为 Cron 验证准备测试专用 `CRON_SECRET`，不输出其值。

## Core tracer path

1. 用户 A 从主导航进入 `/checklists`，看到未过期默认视图和创建入口，验证 **AC-1**、**AC-8**。
2. 创建包含名称、八色主题之一、未来本地截止时间和两个清单项的清单，保存后进入详情并返回列表确认持久化，验证 **AC-2**、**AC-6**、**AC-7**。
3. 点击一个清单项的详情区域，确认计数和部分未确认状态立即更新；再次点击取消；连续快速点击验证节流。默认模式点击右上详情不得切换状态；进入批量管理后点击左下删除、右下编辑不得改变确认状态或选择，验证 **AC-5**、**AC-16**、**AC-19**、**AC-26**。
4. 编辑名称、主题、截止时间和嵌入项：用固定新增器连续添加重复详情项目、在卡片 Dialog 中修改一个既有项、删除一个未保存项和一个既有项后保存，刷新详情并在当前清单的已删除项目 Dialog 中确认事务结果，验证 **AC-3**、**AC-4**、**AC-21**、**AC-22**、**AC-23**。

## Validation and atomicity

- 创建和编辑分别尝试零个有效项、201 个有效项、空白名称、超长字段、非法主题、过去截止时间和 offset free 时间，验证 **AC-2**、**AC-3**、**AC-4**、**AC-7**。
- 创建页确认已添加列表初始为空且页面始终只有一个详情新增器；有效添加后新增器清空、焦点回到详情，每次新增置顶且连续新增后最后添加的项目在前；空白或超长内容保留并定位错误，相同详情可重复添加，验证 **AC-4**、**AC-21**。
- 新增项目后确认它排在最前，保存并刷新后按 (createdAt DESC, createdOrder ASC) 展示，同时间批次保持提交顺序；删除和恢复后确认原 createdAt 与 createdOrder 不变并回到原排序位置，验证 **AC-5**。
- 编辑页确认当前有效项全部以卡片展示；编辑 Dialog 预填目标内容，取消不改变卡片，保存只更新目标卡片，删除先经过二次确认且不会触发确认状态切换，验证 **AC-19**、**AC-20**、**AC-22**。
- 在表单编辑 Dialog 中分别点击保存和按 Ctrl 加 Enter，确认只更新对应本地草稿。放入足够多的项目并连续调整项目网格 content box，确认卡片在当前容量内连续缩小、低于 `12rem` 前才减列、减列后轨道等宽且卡片不超过 12.5rem，整体居中、gap 不变、最终单列，且每张卡片宽高相等。删除按钮在左、编辑按钮在右，验证 **AC-19**、**AC-22**、**AC-25**。
- 检查创建和编辑表单底部操作区，确认取消和保存按钮都使用共享 `Button` 的 `md` 尺寸，主按钮文本始终为“保存”，验证 **AC-20**、**AC-25**。
- 在详情页先进入批量管理，再打开项目编辑 Dialog，分别点击保存和按 Ctrl 加 Enter，确认详情持久化且父子 revision 同时递增。再制造父级和子项版本冲突，确认 Dialog 保留输入、不自动覆盖并提供刷新处理，验证 **AC-16**、**AC-26**。
- 删除未保存的新项后提交，确认数据库和恢复 Dialog 都无该项；删除既有项后先取消整份编辑，确认数据库未变，再次删除并保存，确认仅后者进入所属清单的已删除项目 Dialog 并出现十秒撤销，验证 **AC-3**、**AC-12**、**AC-22**、**AC-23**。
- 在新增器留下有效、空白和超长的未添加内容并尝试保存，确认都先警告；取消保留内容并恢复焦点，继续保存排除新增器内容，慢响应期间清单字段和所有项目操作均禁用，验证 **AC-20**、**AC-24**。
- 分别从详情和编辑表单尝试删除最后一个有效项，确认被阻止；表单删除其他项后保存并撤销，确认只恢复删除项而不回滚其他编辑，验证 **AC-3**、**AC-4**、**AC-12**。
- 在同一清单创建和恢复完全相同、大小写不同或仅首尾空格不同的详情，确认规范化后仍允许重复；null、空白和超长详情被拒绝，验证 **AC-4**、**AC-13**。
- 检查清单表单的日期文本和日历图标按钮都左对齐。未选择时显示“请选择截止日期时间”，选择后显示选中值，按钮本身只含图标。确认“添加”使用共享按钮并右对齐，主题按钮为 `size-8`，验证 **AC-20**、**AC-25**。
- 使用 NFC 与等价组合字符、`%` 和 `_` 搜索项目详情，确认搜索保持字面语义，验证 **AC-4**、**AC-9**。
- 在事务中注入一个子项失败，确认父级和所有子项都未部分更新且表单输入保留，验证 **AC-3**。
- 两个标签页读取相同 revision，先后编辑、确认或删除，确认后提交者收到冲突且不覆盖先提交者，验证 **AC-16**。
- 无变化保存时确认返回权威聚合且父子 revision 和 `updatedAt` 均不变；逐一确认新增、编辑、确认、删除和恢复项目都会按契约更新父 revision 和 `updatedAt`，验证 **AC-3**、**AC-16**。
- 模拟创建已提交但响应丢失，使用相同 `createRequestId` 和相同规范载荷重试，确认只创建一份清单；同一 ID 配不同载荷返回 `conflict`，新的创建意图使用新 ID。模拟编辑已提交但响应丢失，确认界面标记结果未知、冻结旧 revision 并重取权威详情和已删除项目，而不是宣称回滚或自动套用新 revision，验证 **AC-2**、**AC-3**、**AC-16**。
- 分别让确认切换、详情编辑、单项删除、批量删除和四种恢复 action 在提交后丢失响应，确认客户端先重读权威状态，且不会采用新 revision 静默重放旧意图，验证 **AC-12**、**AC-14**、**AC-16**、**AC-26**。

## Time, filters and search

- 创建多个不同截止时间的清单，确认未过期升序和已过期降序，以及相同时间的 ID 稳定顺序，验证 **AC-8**。
- 保持页面打开直到一个清单过期，确认状态立即改变，未过期视图移除该行，切换到已过期后可见，验证 **AC-6**、**AC-8**。
- 用可控时钟验证正数不足一分钟显示 `1min`，5 分钟显示 danger 样式的“即将到期 5min”，精确 10 分钟不显示 danger，36 分钟显示 `36min`，精确 60 分钟显示 `1h`，精确 5 小时显示 `5h`，5 小时 03 分显示 `< 6h`，精确 24 小时显示 `1d`，3 天 20 小时 40 分显示 `> 3d`，到期显示过期，验证 **AC-27**。
- 调整客户端时钟并让页面进入后台再恢复，确认以 `serverNow` 校准且旧查询响应不会覆盖新结果，验证 **AC-8**、**AC-10**。
- 检查列表、详情、编辑、两类回收站读模型和每个成功写入都返回 `serverNow`；确认客户端用 `performance.now()` 推进时间，并在页面恢复可见或写入成功后重新校准，验证 **AC-6**、**AC-8**、**AC-12**、**AC-27**。
- 在有夏令时的 IANA 时区提交原始 `localDateTime` 和 `timeZone`，输入不存在和重复的本地时间，确认前者报错、后者采用较早偏移并显示时区；秒或毫秒非零被拒绝，未改变的历史 UTC 时刻允许保留，跨时区仍显示同一 instant，验证 **AC-7**。
- 以清单名称和项目详情搜索，并组合四种确认筛选和两种过期视图。确认 URL 可复制、刷新可恢复、空搜索可清除，验证 **AC-9**。
- 输入首尾空白、大小写变体、NFC 等价字符以及 1、2、100 和 101 个 Unicode code point，并快速输入多个字符，确认规范化、数据库 collation、防抖和长度规则，验证 **AC-9**、**AC-18**。
- 篡改游标签名，并分别跨 owner、筛选、规范搜索值和 `asOf` 复用游标，再测试过期游标，确认全部在数据库查询前被拒绝，验证 **AC-10**、**AC-15**。
- 在滚动批次之间让时间跨过截止点，确认客户端重载实时 keyset 首批而不是把旧游标继续追加，验证 **AC-8**、**AC-10**。
- 在另一会话修改未加载记录的截止时间或确认状态，确认结果去重且下一次首批刷新纠正实时 keyset 允许的暂时遗漏，验证 **AC-8**、**AC-10**。

## Virtualization and responsive behavior

- 生成超过 72 个结果，确认首屏 24 条，滚动分别加载后续批次，不出现页码、重复或缺失记录，验证 **AC-10**。
- 模拟后续加载失败，确认已加载结果保留且行内重试能继续，验证 **AC-10**、**AC-20**。
- 调整内容容器而不只调整视口，在 639、640、1087、1088、1399 和 1400 像素检查 `lg` 网格、`md` 网格、80 像素 `md` 列表和 64 像素 `sm` 列表。另用组件测试验证 96 像素 `lg` 列表变体，验证 **AC-11**。
- 在清单详情页和清单表单直接测量项目网格 content box 与卡片 border box。固定 `gap-3` 并放入至少 N 个项目，以根字号计算每个 `N × 12rem + (N - 1) × gap-3` 阈值，在阈值上下各取样，确认卡片先在 N 列容量内连续缩小，只有下一步会低于 `12rem` 时才变为 N 减一列。确认减列后轨道等宽且卡片不超过 12.5rem，整体居中、gap 不变，卡片宽高误差不超过 1px，最终为单列；多行时不完整的末行继续对齐活动轨道，验证 **AC-19**、**AC-20**、**AC-25**。
- 分别用 0、1、2 个项目、恰好满行和多出一个项目验证活动列数受项目数量限制。确认宽高均在 12rem 至 12.5rem，少量项目达到上限后两侧余白相等（允许 1px 舍入误差），gap 不变，验证 **AC-19**、**AC-25**。
- 把调试或嵌入环境中的项目网格 content box 压到小于 `12rem`，确认卡片仍保持至少 `12rem` 的正方形，两个底部操作按钮和内部布局不变，只有网格包装层局部横向滚动且页面无横向滚动，验证 **AC-19**、**AC-20**、**AC-25**。
- 使用无空格长字符串和 2000 code point 详情分别检查 `lg`、`md`、`sm` 卡片现有尺寸变体。确认生产项目网格移除非正方形比例与固定或最小高度冲突，文本槽可以收缩并截断，card border box 仍为正方形，验证 **AC-4**、**AC-19**、**AC-20**。
- 用超长名称和详情确认清单项详情区域占满剩余高度、允许换行并在超出时显示多行省略号，同时验证桌面 `title` 和移动端显式详情按钮，验证 **AC-11**、**AC-19**。

## Delete, undo, trash and batch

- 删除清单和清单项时分别取消和确认 AlertDialog。确认后在十秒内撤销，刷新后数据仍恢复，验证 **AC-12**。
- 从清单详情打开已删除项目 Dialog，确认只出现当前清单的项目，支持分页、空、加载、失败、重试与恢复；`/checklists/trash` 只显示清单，不再提供项目模式，验证 **AC-13**、**AC-20**、**AC-23**。
- 确认已删除项目 Dialog 没有搜索输入，每个批次按删除顺序覆盖完整父级结果，不进行仅针对已加载行的本地过滤，验证 **AC-23**。
- 删除清单前先单独删除一个子项，再删除并恢复父级，确认普通子项恢复可见而此前单独删除的项仍在该清单详情的已删除项目 Dialog，验证 **AC-13**、**AC-23**。
- 在父级删除时尝试恢复子项，确认被阻止并提示先恢复父级，验证 **AC-13**。
- 将父级有效项目数准备为 200，再尝试恢复一个子项，确认返回容量冲突且数据库不改变，验证 **AC-13**、**AC-16**。
- 把删除时间置于恢复窗口两侧，确认三十天内可恢复，超过三十天立即不可恢复，验证 **AC-12**、**AC-13**。
- 进入批量管理，选择已加载的若干项，改变搜索或筛选确认选择清空。重新选择后取消确认，再确认删除并整批撤销，验证 **AC-14**。
- 在批量模式验证卡片点击和键盘切换选择、独立按钮打开详情、100 项上限、移出结果清除选择和虚拟卸载后的焦点去向，验证 **AC-14**、**AC-20**。
- 在批量确认后让其中一项 revision 冲突，并分别制造整批撤销的过期和容量冲突，确认整批没有部分结果且冲突项可识别，验证 **AC-14**、**AC-16**。
- 分别调用 `restoreChecklist`、`restoreChecklistItem`、`restoreChecklistItems` 和 `restoreChecklists`，验证输入 revisions、原子性、返回 revisions、计数与 `serverNow`；聚合编辑撤销只恢复对应 `updateChecklist.deletedItems`，详情批量删除撤销只恢复对应 `softDeleteChecklistItems.items`，验证 **AC-12**、**AC-13**、**AC-14**、**AC-16**、**AC-35**。
- 检查每个删除响应的 `undoVisibleUntil` 都来自数据库事务时间且约为 `serverNow + 10s`，客户端时钟调整不改变其可见截止，验证 **AC-12**。
- 删除父清单后尝试确认、编辑和删除子项，确认普通入口表现为不存在，只允许恢复父级，验证 **AC-13**、**AC-15**。

## Authorization and failure safety

- 未登录访问每条页面、Route Handler 和 Action，确认使用现有登录引导或 401 契约，验证 **AC-1**、**AC-15**。
- 用户 B 使用已知的用户 A 清单和项目 ID 读取、编辑、确认、删除和恢复，确认全部表现为不存在且无数据泄露，验证 **AC-15**。
- 以 ADMIN 或 ROOT 身份通过普通产品路径尝试读取别人的清单，确认没有隐式越权，验证 **AC-15**。
- 注入数据库临时故障和未知异常，确认页面可重试、HTTP 状态正确、客户端无 Prisma 信息、日志无名称、详情、令牌和请求正文，验证 **AC-15**、**AC-20**。
- 检查成功导航和焦点：创建与聚合编辑进入详情，清单删除回列表，项目恢复保持 Dialog 打开并聚焦下一恢复按钮或入口，清单恢复留在回收站并聚焦可用目标，验证 **AC-20**、**AC-23**。

## Cron and database

- 在环境缺少 `CRON_SECRET`、请求不带授权、授权错误和授权正确时调用清理 Route Handler，确认前三者 fail closed 且不查询数据库，正确授权执行，验证 **AC-17**。
- 准备超过三十天、恰好三十天和未满三十天的数据，运行清理并确认只有符合条件的数据物理删除。重复运行结果不变，验证 **AC-12**、**AC-17**。
- 准备父级及其级联子项合计超过 500 条并并发运行两个清理请求，确认每批实际删除记录不超过 500、单个最多 201 条的聚合保持完整、`SKIP LOCKED`、锁内重验和无重复副作用，验证 **AC-17**。
- 分别注入连接中断、序列化失败、死锁和不可重试错误，并准备多批积压，确认仅前三类按 50 和 100 毫秒退避最多重试两次，Route Handler 声明 60 秒 `maxDuration` 并在第 55 秒停止开启新批次，后续受保护调用可以续跑，验证 **AC-17**。
- 让恢复与清理竞争同一父子集合，确认统一锁顺序、资格重验和无死锁或误删，验证 **AC-13**、**AC-16**、**AC-17**。
- 检查 PostgreSQL 查询计划和目录，确认外键索引、活动部分索引、列表复合索引与详情 trigram GIN 索引存在且相关查询可使用，并确认不存在项目详情唯一索引，验证 **AC-18**。
- 从空环境执行唯一的清单 migration，确认它直接创建最终 `Checklist` 和 `ChecklistItem`，项目从创建时就只有必填 `TEXT detail`，重复详情可写且最终部分 trigram 索引可用。确认 migration 不包含旧 `name` 字段、中间索引、`DELETE`、`DROP`、`ALTER` 或 procedural block，并通过未放宽的 staging SQL 安全分类器。确认 `app_migrator` 创建对象后，既有 default privileges 只给 `app_runtime` 所需最小权限，验证 **AC-4**、**AC-18**。
- 检查名称、详情、主题 allowlist、正 revision、正 createdOrder、唯一键和外键约束，并用普通空格、制表符、换行、不换行空格和全角空格测试服务端与数据库边界，验证 **AC-4**、**AC-18**。
- 确认迁移只存在于 `prisma/postgres`，从空库重放成功，业务代码没有 legacy MySQL 或生成客户端导入，验证 **AC-18**。
- 以 Supabase `anon` 和 `authenticated` 数据库角色尝试直接访问新表和序列，确认权限被拒绝；应用运行角色仍具有所需最小权限，验证 **AC-18**。
