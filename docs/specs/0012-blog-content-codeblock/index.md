# 0012. Blog 正文与代码块展示修复

**Date**: 2026-10-20
**Status**: Accepted

## Summary

文章详情和编辑预览共用一套 Markdown 展示规则。正文采用紧凑阅读密度，代码块随四主题显示克制的语法配色，默认横向滚动并允许逐块切换换行。实现沿用现有依赖和共享组件，不改变文章数据、发布流程或权限。

## Requirements

**User stories**:

1. 作为读者，我希望标题、段落和各类 Markdown 内容有清晰层级，阅读长文时不用依靠猜测区分结构。
2. 作为读者，我希望代码保持缩进和逻辑行，能按需要换行，并准确复制代码内容。
3. 作为作者，我希望预览和公开详情使用同一套正文规则，主题切换后仍保持一致。

**Acceptance criteria**:

1. **AC-1**: 文章标题和正文建立阅读密度，正文为 `0.9rem`、行高 `1.5`，代码为 `0.875rem`、行高 `1.4`。标题下方总留白为 8px，上方总留白由原值减半至 12px。正文具有清晰的标题、段落、分隔线、列表、引用、链接、行内代码、表格、图片和只读任务列表样式，保留当前主阅读栏最大宽度。
2. **AC-2**: 详情和编辑预览使用同一个正文渲染组件与相同的解析插件、样式和代码块，不再各自维护渲染分支。相同 Markdown 产生相同的内容结构、标题锚点和文本规则，容器宽度只影响自然换行。
3. **AC-3**: 有语言、无语言、未知语言和空代码块均经过同一 CodeBlock。只有真实传入的标题才显示标题，语言缺省时显示“纯文本”，不出现 `test` 占位标题。高亮失败或语言不支持时保留纯文本代码和操作入口。
4. **AC-4**: 代码展示与复制使用同一代码文本源，不调用 `trim()`，不删除内部空行、首尾空白或缩进，不复制行号和工具栏。精确空白以共享正文实际收到的 Markdown 及其解析后的代码文本、直接调用时的 `CodeBlock.code` 为基准；Markdown 解析自身的换行规范化不被当作额外内容编辑。本轮不改变编辑器已有的上游换行转换。
5. **AC-5**: 每个代码块默认横向滚动，显示原始逻辑行号；通过“自动换行”按钮可切换当前块的软换行，按钮用 `aria-pressed` 表达状态。软换行不增加逻辑行号，不改变代码文本或其他代码块的状态，内容改变或组件重新挂载后恢复默认模式。
6. **AC-6**: light、dark、sugar、warm 下，正文、代码背景、边框和字体使用现有主题 token。语法只区分默认文本、关键字、字符串和注释四组颜色，三组专用前景色与实际代码背景的对比度均至少为 `4.5:1`；不再使用固定 Dracula 主题的颜色和字体。
7. **AC-7**: 代码块复用共享面板与按钮，使用 default 内边距，内部 gap 为 `.25rem`，按钮之间的 gap 为 `.5rem`，上下外边距各为 `.5rem`。复制与换行操作沿用共享 Button 的默认图标尺寸与内边距，具有中文可访问名称和可见焦点；代码可通过键盘选择和滚动，默认隐藏原生滚动条。
8. **AC-8**: 复制成功通过勾选图标和状态区域反馈；剪贴板不可用或写入失败时显示“复制失败，请手动选择代码”，保留可选择的代码，允许再次尝试。快速重复复制、内容更新和卸载不会留下旧计时器或把旧结果显示到新代码上。
9. **AC-9**: 长链接、长代码和宽表格只在各自允许的区域换行或滚动，不使整页产生意外横向滚动；图片保持原始比例且不超出正文宽度。代码工具栏在窄屏可换行，控件及焦点不会被裁切。
10. **AC-10**: 公开详情保留服务端页面和正文输出，仅代码块交互需要客户端状态。主题配色由 CSS 变量解析，不按客户端读取主题来选择首次渲染内容，不增加主题闪烁、hydration 警告或新的全局主题状态。
11. **AC-11**: 现有文章查询、编辑权限、数据保存内容及正文标题 ID 规则保持兼容；不执行 Markdown 中的原始 HTML，不增加不安全协议、脚本执行、上传或后台请求。本功能不新增数据库模式、API、环境变量、外部服务或包依赖。
12. **AC-12**: Album 新增可独立使用的正文与代码块安全展示，覆盖四主题、代码语言回退、空白保留、长行、换行切换和复制反馈；演示只使用固定本地内容，不加载完整业务编辑器或调用生产数据接口。
13. **AC-13**: 相关 Vitest、真实浏览器检查、lint、类型检查、build 和 Playwright 验证通过。公开阅读可独立检查，作者预览与发布一致性使用安全测试账号验证；环境或账号不足的部分明确记录为未验证，不能用 Album 替代真实业务闭环。

## Decision

**Chosen option**: Option 2: 共享正文渲染，逐处接入现有页面。

新增一套无业务依赖的 `BlogMarkdown` 与独立 `CodeBlock`，详情、预览和安全展示复用它们。继续使用当前 `react-markdown`、`remark-gfm`、`rehype-slug` 和 `react-syntax-highlighter`，不更换解析引擎或引入第二套组件体系。（basis: scope 28，`src/AGENTS.md`，spec 0007）

**Implementation skills**: `typescript-react-patterns` (`asyrafhussin/agent-skills`, `.agents/skills/typescript-react-patterns/`) · `tailwind-css` (`paulrberg/agent-skills`, `.agents/skills/tailwind-css/`)

## Feature design

### Scope and confirmed choices

用户最终确认紧凑阅读密度、默认横向滚动加逐块换行开关、克制的语法配色，以及仅列项目参考来源。下方排版表和代码表面规则记录本轮最终值，详情、编辑预览与 Album 共同遵循。设计来源是现有 `design.md`、主题 token 和共享组件，不新增独立视觉风格。（basis: 本次设计对话，`design.md`）

2026-10-20 用户后续确认：本轮涉及的按钮均引用 Album 展示的 `src/components/ui/button`，复制与换行使用 `size="icon"`，直接沿用共享 Button 的默认图标尺寸与内边距；复制成功显示勾选并在一秒后恢复。取消点击区域至少 44×44 的要求，不在调用处额外添加 `min-h-11`、`min-w-11`。（basis: 本次用户明确调整）

同日用户进一步要求缩小代码行距，代码语言使用现有 Tag 组件，代码块容器最终采用 `inset-sm` 阴影；本轮将行高取为 `1.4`，默认面板密度与内边距继续保留。（basis: 本次用户明确调整，行高数值为“小一些”的实现取值）

本规格承接 scope 28。为保证正文真实可用，本轮直接接入编辑预览，并完成代码块自身的点击区域和复制反馈；scope 29、33 继续负责其余阅读操作与编辑器工具栏。目录配色及进度属于 scope 30，页面空状态属于 scope 31，跨页面容器收口属于 scope 32。保持既有 `blog-container`、`blog-content` 标识及标题 slug 生成规则，不在本轮重新设计目录。

现有 `BlogEditor.onContentChange` 会在部分换行前添加两个空格，包括代码围栏内部；预览和持久化使用的是转换后的 `blogData.content`。本轮的“不额外改写”从这个实际输入边界开始，不承诺编辑器粘贴前文本逐字保留。精确空白测试直接为共享正文或 CodeBlock 提供固定输入；真实作者流程比较当前 `blogData.content`、提交后的持久化内容及公开展示。调整编辑器输入转换或无行为的“保存”按钮仍归 scope 33。

| Component | Contract | Responsibility |
| --- | --- | --- |
| `src/components/Blog/BlogMarkdown.tsx` | `content: string` 必需；`id?: string`、`className?: string` 可选 | 无业务依赖的共享 Markdown 入口，采用相同 GFM（表格、任务列表等扩展）和标题 slug 插件 |
| `src/components/Blog/CodeBlock.tsx` | `code: string` 必需；`language?: string`、`title?: string` 可选 | 代码语义结构、语言回退、行号、逐块换行和复制工具栏 |

| `src/components/NotionBlock/index.tsx` | 保持现有具名 `CodeBlock` 导出兼容 | 重新导出正式 CodeBlock，现有 Notion 调用传入真实 caption，不保留第二份实现 |

组件 props 使用 interface 和原生 React 属性类型；只透传与实际 DOM 相符的属性，不使用 `any` 或强制断言伪造解析节点结构。共享正文组件不导入数据库、认证或服务端操作，因此也能被客户端预览使用。（basis: `typescript-react-patterns`，`src/AGENTS.md`）

详情继续为服务端页面。共享正文不声明客户端状态；代码块和复制按钮管理自己的交互状态。编辑器作为现有客户端入口导入同一正文组件，不因此把公开详情整体变为客户端页面。

### Parsing and document structure

1. 只维护一份插件配置和元素映射。正文标题保留 Markdown 的 `h1` 至 `h6` 等级，不因字号设计重排等级；文章标题在正文外保持独立标题。保留 `rehype-slug` 当前的锚点生成行为和重复标题去重，不增加依赖文章数据库内容的 ID 算法。
2. 围栏及缩进代码块从整个 `pre` 节点替换为 CodeBlock，行内 `code` 单独展示；不得仅替换 `code` 后把面板、按钮和另一个 `pre` 嵌进外层 `pre`。传给正文 DOM 的属性不包含解析器内部 `node`。
3. 代码文本取自解析节点的文本内容，不从已经高亮的 DOM 抓取，不用会在多个文本节点之间插入逗号的数组转字符串方式。Markdown 解析器对行尾的规范化以及围栏语法消解保留，渲染层不继续删除或补齐空白。直接调用 CodeBlock 时则原样使用 `code` 字符串。
4. 语言来自代码块的语言标记，完整读取标识，支持带 `+`、`#` 和连字符的名称。匹配不区分大小写；常用别名 `js/jsx/ts/tsx/sh/bash/json/css/html/md` 对应现有高亮库支持的语法。未标记或不支持的语言使用纯文本，不为未知标识下载语法或抛出整页错误。
5. 标签仅展示实际的标题和语言。语言缺省显示“纯文本”；未知语言显示其安全文本名称并附“纯文本”说明。空代码不丢失工具栏，空块行号栏不生成虚构行。
6. 不启用原始 HTML 解析或执行插件。链接和图片继续经过现有 Markdown 默认的 URL 安全处理，不放宽协议白名单；图片保留作者 alt，使用按需加载、宽度上限和自动高度，不新增图片裁剪或预览弹窗。

### Typography and spacing

字体来源以 `src/app/globals.css` 的 `--font-sans`、`--font-mono` 为准。`design.md` 提到的字体名称与当前 token 的回退字体存在差异，本轮不引入字体下载或修改全站字体；Blog 和代码使用同一现行 token 来源。（basis: `design.md`，`src/app/globals.css`）

| Content | Confirmed value or existing scale | Treatment |
| --- | --- | --- |
| 正文 | 新 `--text-blog-body: 0.9rem`、`--leading-blog-body: 1.5` | 主题正文色 |
| 文章标题 | 新 `--text-blog-title: 1.875rem`、`--leading-blog-title: 1.3` | 加粗，允许长标题自然换行 |
| 正文 h1、h2、h3 | 现有 `text-2xl`、`text-xl`、`text-lg` | 半粗，行高 1.4 |
| 正文 h4、h5、h6 | 现有 `text-base`、`text-sm`、`text-sm` | 半粗，按真实语义级别输出 |
| 代码与行号 | 新 `--text-blog-code: 0.875rem`、`--leading-blog-code: 1.4` | `--font-mono`，行号不可选且对辅助技术隐藏 |
| 内容容器内边距 | `--spacing-panel-inset-default: .75rem` | 默认密度，紧凑表格单元格明确使用 compact |
| 正文块间距 | `--spacing-panel-gap-compact: .25rem` | 列表与引用内部块间距一致 |
| 标题上、下留白 | `--spacing-blog-heading-before: .75rem`、`--spacing-blog-heading-after: .5rem` | 普通正文标题上方 12px、下方 8px；首个标题和连续标题遵循下文例外；相邻代码块另计其 margin |
| 代码面板与工具栏内部 gap | `--spacing-panel-gap-compact: .25rem` | 与默认内边距分别控制 |
| 代码按钮之间 gap | `--spacing-panel-gap-default: .5rem` | 仅操作区按钮间距 |
| 代码块上下 margin | `--spacing-panel-inset-compact: .5rem` | 上下各 8px，叠加正文块间距 |

新字号和行高值在唯一全局 token 入口定义，组件只引用，不在组件中重复数值。文章正文外层面板采用 default 内边距和直接子元素 gap；正文内部清除浏览器默认 margin，按用户最新要求采用 compact gap（`.25rem`，当前 4px），列表和引用内部的块间距同步采用 compact。正文行高为 1.5，标题下方总留白保持 8px，上方总留白保持 12px，为原有 default gap 与 comfortable 顶部内边距之和的一半。两者由 `--spacing-blog-heading-after` 和 `--spacing-blog-heading-before` 派生，正文标题扣除实际 compact gap 后设置内部留白，避免总间距随 gap 缩小；首个正文标题顶部不另加留白，连续标题不叠加后一标题的顶部内边距。文章主标题下方也采用 8px，现有面板默认内边距继续保留。列表缩进和引用内边距使用现有间距尺度，嵌套列表保留各自标记，不依赖全局 reset 的默认结果。

引用采用主题边框与正文色，不使用警告或危险配色。行内代码使用主题背景或 muted 表面和正文色，允许长文本局部折行。链接使用正文色与持续可见的下划线，以现有主色表达下划线强调及焦点；不直接把暗色主题中对比不足的主色作为小字号链接文字。

表格保留真实 `table`、表头和单元格语义，只有外层局部滚动；代码、表格滚动包装的零内边距例外在调用处显式表达，其内部没有需要额外阴影留白的子面板。图片不增加固定比例；正文样式作用域限定在 `.blog-markdown`、`.blog-article-title` 和代码块类名，不恢复全站标题或段落 reset。（basis: `design.md`，`tailwind-css`）

### Code surface and syntax colors

CodeBlock 使用 `NeuPanel elevation="inset-sm"`，保留 default 内边距；面板和工具栏内部 gap 使用 compact（`.25rem`），操作区按钮之间使用 default gap（`.5rem`），上下各加 `.5rem` margin，与正文块 gap 分别计算。工具栏是可换行的语言和操作区域，代码语言复用现有 Tag，未知语言和缺省语言也通过同一 Tag 展示；长语言名称可在标签内换行。代码背景为 `--background`，边框、圆角、阴影沿用共享组件，普通语法为 `--foreground`。

新增以下语法专用 CSS 变量，放在现有四主题区块中。它们只表示代码语法，不用于成功、危险、警告或主要操作状态。高亮输出使用 CSS class 与这些变量，移除固定 Dracula 的内联颜色和字体。（basis: `design.md` 的主题与状态色规则，spec 0007 的单一样式来源）

| Theme | `--code-keyword` | `--code-string` | `--code-comment` |
| --- | --- | --- | --- |
| light | `#5b3c88` | `#285c37` | `#4c555f` |
| dark | `#c4b5fd` | `#a7d7ad` | `#9ca3af` |
| sugar | `#6a3162` | `#235c3a` | `#68575a` |
| warm | `#65356e` | `#355b30` | `#6d4a7a` |

关键字、内置类型和布尔字面量归 keyword；字符串、字符和属性值归 string；注释、文档声明归 comment；其余 token，包括标点、数字和函数名，继承普通前景色。行号使用 comment 色，复制成功使用现有成功色和勾选图标，并通过状态区域提供中文反馈；失败保留可见文字。

### Wrapping and local state

每块状态为 `wrap: false | true`，初始 `false`，只存在组件内存中，不写入 URL、Cookie、localStorage 或数据库。内容或语言改变时恢复 `false`，标题和主题变化不重置用户当前选择。按钮标签固定为“自动换行”，`aria-pressed` 为当前值。

关闭换行时，代码保留空白与逻辑行，滚动区域水平滚动。开启时采用软换行，在必要处拆开无空格长串，允许代码块高度增长，不改变代码字符串。每个源逻辑行只显示一个行号，软换行后的续行对齐代码列，不新增行号；空字符串没有行号，末尾的换行不会被渲染层删去。

行号将 CRLF、LF 或 CR 各视为一个换行分隔符；末尾仅作为终止符产生的最后一个空分段不另行编号，代码字符串本身不改变。精确样例：`""` 没有行号，`"a\n"` 只有第 1 行，`"a\n\n"` 有第 1、2 行且第 2 行为空，`"\n"` 有一个空的第 1 行。视觉软换行不参与这些计算。

### Copy feedback and failure handling

复制按钮使用共享 Button 的图标尺寸，默认显示 `file_copy`，中文可访问名称为“复制代码”，调用浏览器剪贴板写入当前代码文本。状态为 `idle → copying → copied | failed`；写入期间阻止重复提交，成功时切换为 `check` 图标，状态区域分别提供“已复制”或约定失败文字，并使用 `aria-live="polite"`。成功文字供辅助技术读取，失败文字保持可见。

成功反馈在一秒后恢复；失败反馈保留到下一次尝试或代码内容改变。每次写入关联当前代码版本，旧版本的异步完成不能覆盖新版本状态；卸载和内容改变清理反馈计时器。剪贴板不存在或抛错都进入 failed，代码保持可选择。不自动读取剪贴板、不注入隐藏输入框、不记录代码内容。

复制和换行按钮使用共享 Button 的 `size="icon"`，尺寸与内边距和 Album 的默认图标按钮一致，调用处不设置额外的最小点击区域尺寸；换行按钮显示 `wrap_text` 图标，保留中文可访问名称、悬浮提示和 `aria-pressed`。局部滚动区域提供中文可访问名称和键盘焦点；没有溢出时不增加无意义的滚动提示。减少动态效果时关闭本组件装饰性过渡和滚动动画，不新增持续动画。

| Surface or action | Produced value | Source |
| --- | --- | --- |
| 公开详情 | 标题、Markdown 正文 | 现有 `getBlogById` 的 `blog.title`、`blog.content` |
| 编辑预览 | 当前 Markdown | 现有 `BlogEditor.onContentChange` 转换后的 `blogData.content`，通过编辑器 `blog.content` 属性传入；共享渲染器不额外改写 |
| 作者持久化验证 | 实际存储内容及详情 | 现有“提交”按钮调用 `handleSubmit`；成功后进入对应公开详情，不使用无行为的“保存”按钮 |
| 共享正文 | 结构、列表、表格、链接、图片 | 当前 Markdown 字符串，经同一解析与 GFM 插件处理 |
| 标题导航兼容 | 标题 ID | 同一 `rehype-slug` 输出，保留现有生成规则 |
| 代码块 | 原始代码文本、语言标记 | 解析后的代码节点；直接使用时来自 CodeBlock props |
| 可选标题 | 工具栏标题 | `title` prop，现有 Notion 调用来自真实 caption；Markdown 默认不提供 |
| 语法与字体 | 颜色、字族与密度 | 当前主题 CSS 变量、上述新 token 和排版表 |
| 行号 | 每个逻辑行的序号 | 当前代码按换行分隔后的逻辑行，空字符串不编号 |
| 换行状态 | 软换行和按钮选中 | 当前代码块本地布尔状态 |
| 复制结果 | 状态与文字 | 当前代码版本的剪贴板 Promise 结果和规定反馈文字 |
| Album | 演示内容、状态和四主题 | 固定本地 fixture、组件 props 与既有局部主题容器 |

本规格没有新 HTTP 接口、服务端 Action 或持久数据模型。公开正文仍可匿名阅读，编辑预览继续依赖现有编辑入口的认证和权限；两者只是内容输入来源不同，不改变任何授权边界。

### Security and configuration

沿用现有 Markdown 安全输出，不渲染原始 HTML，不允许脚本协议，不通过高亮执行代码。公开页面和编辑器的角色权限不因共享组件变化。剪贴板写入仅由用户主动复制触发，日志不包含代码、文章内容或剪贴板内容。本功能不需要新的运行配置、密钥或服务权限。

### Safe showcase and verification

在 Album 注册独立 `blog-markdown` 的 ready 条目，由一个本地展示模块覆盖 BlogMarkdown、CodeBlock 和复制行为，维护源码导出覆盖映射。原有 `blog`、`editors` 与 `notion-message` 家族只更新真实来源归属，不为展示本功能而整体标记 ready。新渲染器不导入完整 MarkdownEditor、认证 Provider 或业务 Action。（basis: `src/AGENTS.md`，spec 0008）

核心场景包括多级标题、嵌套列表、引用、任务列表、链接、宽表格、固定本地图片、有语言代码、无语言代码、未知语言、空代码、缩进和首尾空行、两个独立代码块及超长逻辑行。剪贴板失败通过测试或明确注入的本地展示适配器模拟，不修改浏览器安全设置。

运行环境准备后，先用一篇已有公开文章确认服务端真实阅读，再用安全测试账号检查编辑预览，通过现有“提交”操作持久化，确认成功并进入公开详情后比较。可视检查覆盖 1280×800 和 390×844 视口、四主题、键盘、局部横滚、换行及减少动态效果。每项证据记录页面、主题、视口和观察结果，不因组件测试通过而声称业务闭环已验证。

### Critical test scenarios

1. 已有公开文章完整阅读，作者编辑同一内容并预览、通过现有“提交”操作持久化和重读，比较实际输入、正文结构及标题锚点，验证 **AC-1**、**AC-2**、**AC-10**、**AC-11**、**AC-13**。
2. 语言回退、空代码、特殊语言标记、首尾空白和末尾换行，严格比较复制文本，验证 **AC-3**、**AC-4**。
3. 两个代码块独立换行，软换行行号、内容变化、快速复制和旧异步结果隔离，验证 **AC-5**、**AC-8**。
4. 四主题实际颜色对比、宽窄视口局部溢出、点击区域、键盘和减少动态效果，验证 **AC-6**、**AC-7**、**AC-9**、**AC-10**。
5. Album 只使用固定本地场景，检查高亮与剪贴板失败、重置和源码归属映射，验证 **AC-3**、**AC-8**、**AC-12**、**AC-13**。

## Build plan

1. 打通最小真实阅读路径：建立共享正文入口、代码块边界和 scoped 样式，先接入公开详情，保留已有查询和标题锚点，用标题、段落及一个代码块确认服务端页面到真实数据的阅读路径，满足 **AC-1**、**AC-2**、**AC-3**、**AC-10**、**AC-11**。
2. 完成代码块全部行为：统一围栏识别与语言回退，保留代码空白，加入逐块换行、逻辑行号和复制状态隔离，满足 **AC-3**、**AC-4**、**AC-5**、**AC-7**、**AC-8**。
3. 完成完整正文、四主题与溢出：加入排版 token 和代码专用色，覆盖列表、引用、行内代码、表格、图片及长内容，测量实际渲染对比度、滚动和点击区域，满足 **AC-1**、**AC-6**、**AC-7**、**AC-9**、**AC-10**。
4. 让现有编辑预览接入同一正文，兼容导出正式 CodeBlock，清理两处重复渲染和占位标题；接入独立安全 Album 展示与覆盖审计，不调整保存语义，满足 **AC-2**、**AC-3**、**AC-10**、**AC-11**、**AC-12**。
5. 补齐有意义的解析边界、空白、换行、异步复制及预览一致性测试，按 `verify.md` 完成真实文章、作者预览、四主题、视口和键盘验证，并运行项目规定检查，满足 **AC-1** 至 **AC-13**。

## Consequences

**Positive**:

1. 正文规则、代码内容和颜色各有单一来源，详情、预览与安全展示保持一致。
2. 用户可按当前代码块切换阅读方式，复制结果不受视觉换行影响。

**Negative / tradeoffs**:

1. 紧凑正文的字号与块间距需要持续结合标题留白、宽窄视口和四主题检查阅读效果。
2. 换行开关和复制状态增加少量客户端状态，四主题语法 token 增加持续验证成本。
3. 沿用现有高亮依赖，客户端预览仍承担其既有体积和渲染成本；本轮没有测量依据，不附加更换引擎、缓存或代码虚拟化。

**Neutral**:

1. 不迁移数据、不重写 Markdown、不新增运行配置，可通过回退本次组件接入和 scoped 样式恢复先前表现。
2. 正文源标题等级保持兼容，已有文章自身的标题使用习惯不在本轮批量修订。

## Follow-up

1. scope 29、30、31、32、33 继续承接其余阅读操作、目录、状态、容器和编辑器行为，本规格只处理为正文与代码块交付必需的接入。
2. 全站字体名称与 `design.md` 描述的差异保留为独立设计基线问题，本轮沿用现行字体 token。
