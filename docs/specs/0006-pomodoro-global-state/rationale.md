# Rationale: 0006 · 番茄钟全局响应式状态

## Context

当前番茄钟控制器由 `/tomato` 页面拥有。离开页面后，React reducer、tick、声音、标题和自动同步随组件一起卸载。持久化的 `endAt` 可以在再次进入时恢复正确剩余时间，也可以补记已经结束的当前阶段，但其他页面无法实时显示同一状态，到期结算和同步也可能等到控制器再次挂载。

现有系统已经完成按用户存储、离线 outbox、服务端事件幂等、多标签页同步、冲突处理、月份历史和固定会话时区归档。这些是已验证契约。本次问题是客户端控制器的所有权，不是缺少新的数据库会话模型或通用状态管理基础设施。

共享导航状态需要在运行时更新，但不应迫使无关页面接管番茄钟逻辑。全局化还会扩大插件的生效范围，因此标题、声音、Toast、认证切换和同步结算必须有明确所有者。

## Options considered

### Option 1: 原地提升现有控制器

将现有控制器封装进 Pomodoro 专用 Provider。页面和导航栏通过强类型 Context 消费，现有持久化和服务端契约保持不变。

**Pros**:

1. 直接解决跨页面连续运行和实时显示。
2. 保留 reducer、outbox、幂等和历史实现。
3. 每个标签页仍只有一个控制器，后续共享操作只改一个组件。

**Cons**:

1. 需要重新划分插件、认证生命周期和页面结算回调的所有权。
2. Provider 成为全站常驻客户端逻辑，需要更广的路由回归。

### Option 2: 每个页面重新创建控制器

每个需要显示番茄钟的页面读取 `localStorage` 并调用现有 Hook。页面进入时恢复，离开时卸载。

**Pros**:

1. 单个页面首次接入的改动较小。
2. 不访问番茄钟的页面没有常驻控制器。

**Cons**:

1. 导航仍会重建 tick、声音和同步任务，不是真正的全局响应状态。
2. 页面增加后容易出现重复控制器、行为漂移和更大的组合测试面。
3. `storage` 事件不通知当前写入标签页，不能代替标签页内 Context。

### Option 3: 引入通用应用 Store

新增一个通用全局状态容器，并将 Pomodoro 作为第一个业务区域。其他领域以后可以加入同一 Store。

**Pros**:

1. 所有全局业务状态拥有统一入口。
2. 成熟状态库可以提供细粒度订阅能力。

**Cons**:

1. 当前只有一个明确的全局计时领域，新依赖和通用抽象没有比例相称的收益。
2. 容易让 Todo、Daily、认证和界面状态逐步耦合到高频 tick 的业务 Store。
3. 仍然需要单独解决现有插件、outbox 和认证切换语义。

### Option 4: 浏览器后台服务拥有计时

使用 Service Worker 或其他浏览器后台协调层拥有计时，再向页面广播状态。

**Pros**:

1. 页面生命周期与计时器进一步分离。
2. 可以为更复杂的后台通知和标签页协调提供基础。

**Cons**:

1. 浏览器仍会限制后台执行，不能保证精准常驻计时。
2. 增加消息协议、版本兼容和调试成本，但当前 `endAt` 恢复已经解决关闭页面后的时间正确性。
3. 远超站内跨页面显示的实际需要。

## Rationale

选择原地提升现有控制器。现有番茄钟的数据安全和同步路径已经稳定，最小风险做法是只改变所有权，让一个 Provider 跨路由存活。每页重建不能消除生命周期缝隙，通用 Store 和浏览器后台服务则扩大了问题和运维面。

Provider 保持 Pomodoro 专用，避免高频计时状态成为其他业务的默认容器。状态和操作 Context 分离，让只调用操作的消费者不会跟随 tick 更新。强类型 null Context 和保护 Hook 可以在缺少 Provider 时立即失败，而不是使用伪默认值隐藏挂载错误。

页面历史不进入全局 Provider。它依赖所选日期、固定时区和月份请求身份，只在 `/tomato` 有意义。无重放的 settlement 订阅保留页面在线时的即时更新，页面离开期间仍由数据库和 outbox 作为完整来源，避免建立第二份事件缓存。

Provider 只处理绝对开始和结束时间，不接管页面归档时区。页面先订阅 settlement 再读取月份，并把查询期间收到的规范记录合并进响应。这关闭了无重放订阅与旧查询响应之间的遗漏窗口，同时不要求 Provider 保存事件历史。

普通 tick 不再写 `localStorage`。运行状态已经持有绝对 `endAt`，恢复时可以准确计算剩余时间。只持久化有效转换既保留 0001 的恢复安全，又减少全站常驻后的同步主线程写入。

浏览器可能冻结后台页面，因此全局 Provider 只保证在恢复执行后立即校准，不能承诺墙钟到点时一定运行。恢复和重新登录产生的过期完成仍属于当前用户可见的完成结果，会显示一次 Toast；远端状态同步、停止和跳过不新增 Toast。

不使用功能开关。本次没有数据迁移、服务端接口变化或双写阶段，可以通过一个提交回退 Provider、导航组件和页面消费方式。风险主要集中在认证切换、插件重复和跨路由结算，因此由组件测试和真实流程验证控制。
